1 · File header, includes & conventions

Lines 9–53 — Doxygen file comment (added by documentation pass)

The file-level comment documents six things that were previously implicit:

  • Handle type — all key handles are DSA* cast to jlong. EVP_PKEY* handles are only produced by DSAKEY_createPKey.
  • Key format table — which DER format each function consumes or produces.
  • DSA_ERROR alias — reuses OPENSSL_RSA_FAILED (0x00000038); no dedicated DSA code exists yet.
  • Deprecation warning — OpenSSL 3 deprecated the entire low-level DSA API; migration to EVP_PKEY required before OpenSSL 4.
  • Two sign/verify paths — NONEwithDSA (raw bytes) and SHA*withDSA (live digest context).

2 · DSA_ERROR — error code alias

static const int DSA_ERROR = OPENSSL_RSA_FAILED;

A file-scoped constant that aliases OPENSSL_RSA_FAILED (0x00000038) from OpenSSLExceptionCodes.h. Centralising the error code in one place means only one line needs updating once DSA-specific codes are added. Every setPendingOpenSSLException call in the file uses DSA_ERROR rather than the raw numeric constant.

3 · dsaResult / getDSA / getPKey — handle cast helpers

static helpers

Three one-liner functions that centralise the pointer ↔ jlong casts. Using intptr_t as the intermediate type is the portable, standards-compliant way to convert a pointer to an integer on both 32-bit and 64-bit platforms without relying on implementation-defined behaviour.

FunctionDirectionType
dsaResult(dsa)DSA* → jlongUsed as the return value of every generate/create function
getDSA(id)jlong → DSA*Called at the top of every function that takes a keyId
getPKey(id)jlong → EVP_PKEY*Called in signDigestCtx and verifyDigestCtx which receive an EVP_PKEY* handle
No NULL check in getDSA / getPKey: These functions do not validate the pointer; that responsibility belongs to each caller. This keeps the helpers simple and makes the null checks visible at each call site.

4 · encodeDSA — DER key serialisation helper

static helper static jbyteArray encodeDSA(JNIEnv *env, DSA *dsa, int privateKey)

Encodes a DSA* to DER and returns a new Java byte[]. The same function handles both private and public keys via the privateKey flag. Uses the three-step in-place encoding pattern shared by this file and OpenSSLXECKey.c:

  1. Size query: i2d_DSAPrivateKey(dsa, NULL) or i2d_DSAPublicKey(dsa, NULL) — returns byte count without writing anything.
  2. Allocate Java array: NewByteArray(env, size).
  3. Pin, encode, commit: GetByteArrayElements → i2d_DSA*Key(dsa, &p) into the pinned buffer → ReleaseByteArrayElements(env, result, bytes, 0).

If the second i2d_* call fails (rare, only if the key is corrupted after the size query), DeleteLocalRef is called to prevent a JNI local reference leak before returning NULL.

DER formats produced:

privateKey flagFormatStructure
1 (private)OpenSSL DSAPrivateKeySEQUENCE { version, p, q, g, y, x }
0 (public)OpenSSL DSAPublicKeyINTEGER y (in context of domain parameters)

5 · encodeParameters — DER parameter serialisation helper

static helper static jbyteArray encodeParameters(JNIEnv *env, DSA *dsa)

Identical three-step pattern to encodeDSA but calls i2d_DSAparams to produce the domain parameters only (p, q, g). The DER structure is:

DSAparams ::= SEQUENCE { p INTEGER, q INTEGER, g INTEGER }

Used by DSAKEY_generateParameters and DSAKEY_getParameters.

6 · decodeDSA — DER key deserialisation helper

static helper static DSA *decodeDSA(JNIEnv *env, jbyteArray bytes, int privateKey)

Parses a Java byte[] containing DER-encoded DSA key material and returns a heap-allocated DSA*.

Key implementation details

  • Pins the Java array with getByteArrayElementsSafe (sets a pending exception and returns NULL on failure).
  • Uses a separate const unsigned char* p pointer passed to d2i_* — the function advances this pointer as it parses; the original data pointer remains at the array start for the unpin call.
  • Cleanup before NULL check: cleanupByteArray(..., JNI_ABORT) is called on line 102 before checking whether dsa == NULL. This ensures the JNI pin is always released regardless of parse success or failure.
  • On failure, both a Java exception is set and logOpenSSLError is called to capture the OpenSSL error queue.

7 · DSAKEY_generate (bits overload) — generate fresh key pair

JNI JNIEXPORT jlong JNICALL Java_..._DSAKEY_1generate__JI( JNIEnv *env, jclass cls, jlong contextId, jint bits)

The Java method name DSAKEY_generate is overloaded; the JNI mangling suffix __JI identifies the (long, int) signature — one J (long) for contextId and one I (int) for bits.

The function performs two OpenSSL operations in a single if-chain:

  1. DSA_generate_parameters_ex(dsa, bits, NULL, 0, NULL, NULL, NULL) — generates the domain parameters p, q, g. The NULL seed and 0 seed length tell OpenSSL to use its own random seed. The three trailing NULLs are for an optional counter output, H output, and a progress callback — all unused here.
  2. DSA_generate_key(dsa) — generates the private key x (random) and computes public key y = g^x mod p.

If either step fails, the partially-constructed DSA* is freed before returning 0. The chained || short-circuits correctly because both functions return 1 on success.

8 · DSAKEY_generateParameters — generate domain parameters only

JNI JNIEXPORT jbyteArray JNICALL Java_..._DSAKEY_1generateParameters( JNIEnv *env, jclass cls, jlong contextId, jint bits)

Generates only the domain parameters (p, q, g) without creating key material. Used by the Java DSAParameterGenerator SPI when the application needs a DSAParameterSpec to share across multiple key pairs.

The temporary DSA* (which holds only the parameters, no key) is freed with DSA_free(dsa) after encodeParameters returns — the comment in the source notes that the DSA* is no longer needed once the bytes are encoded.

9 · DSAKEY_generate (params overload) — generate key from existing params

JNI JNIEXPORT jlong JNICALL Java_..._DSAKEY_1generate__J_3B( JNIEnv *env, jclass cls, jlong contextId, jbyteArray parameterBytes)

JNI suffix __J_3B: one J (long) for contextId, one [B (byte array) mangled as _3B for parameterBytes.

Pin parameterBytes
d2i_DSAparams → DSA* (params only)
Unpin (JNI_ABORT)
DSA_generate_key → adds x, y
Return DSA* handle

d2i_DSAparams produces a DSA* with p, q, g populated but x and y at zero/NULL. DSA_generate_key then fills in x and y. The unpin is called before the if (dsa == NULL || DSA_generate_key...)) check — the same cleanup-before-check discipline as decodeDSA.

10 · DSAKEY_createPrivateKey / createPublicKey — import from DER

JNI

Both functions are one-liners that delegate entirely to decodeDSA:

return dsaResult(decodeDSA(env, bytes, 1));  // private
return dsaResult(decodeDSA(env, bytes, 0));  // public

The DER formats consumed:

FunctionFormatOpenSSL parser
createPrivateKeyOpenSSL DSAPrivateKey DER: SEQUENCE { version, p, q, g, y, x }d2i_DSAPrivateKey
createPublicKeyOpenSSL DSAPublicKey DER: INTEGER y (in DSAParams context)d2i_DSAPublicKey
Note on public key format: OpenSSL's d2i_DSAPublicKey expects the internal OpenSSL format (raw INTEGER y), not the X.509 SubjectPublicKeyInfo wrapping. The Java layer is responsible for stripping the SPKI wrapper before calling this function.

11 · DSAKEY_getParameters — export domain parameters

JNI JNIEXPORT jbyteArray JNICALL Java_..._DSAKEY_1getParameters( JNIEnv *env, jclass cls, jlong contextId, jlong keyId)

Recovers the DSA* from the handle, guards against NULL, then delegates to encodeParameters. The parameters (p, q, g) are present in both private and public key handles — this function can be called on either.

12 · DSAKEY_getPrivateKeyBytes / getPublicKeyBytes — export key to DER

JNI

Both delegate to encodeDSA(env, dsa, 1) and encodeDSA(env, dsa, 0) respectively after a NULL guard on the handle. The three-step in-place encoding pattern in encodeDSA avoids any intermediate OpenSSL-allocated heap buffer.

13 · DSAKEY_createPKey — wrap DSA* into EVP_PKEY*

JNI JNIEXPORT jlong JNICALL Java_..._DSAKEY_1createPKey( JNIEnv *env, jclass cls, jlong contextId, jlong keyId)

Produces a second, independent handle from an existing DSA key handle. This is necessary because OpenSSLSignature.c operates on EVP_PKEY* handles (via EVP_DigestSignInit / EVP_DigestVerifyInit), while DSA keys are stored as DSA* handles in the Java layer.

Ownership and reference counting

EVP_PKEY_set1_DSA(pkey, dsa) — the set1_ prefix means OpenSSL takes a reference to the DSA*, incrementing its internal reference count. After this call:

  • The original DSA* handle (keyId) still exists and must still be freed via DSAKEY_delete.
  • The new EVP_PKEY* handle must be freed separately (currently via RSAKEY_delete or a future dedicated function).
  • The underlying DSA object will only be deallocated when both references are released.
Two handles, one object: After DSAKEY_createPKey, Java holds two jlong handles that both point to the same underlying DSA key material (via different wrappers). Both must be deleted independently, and deleting one does not invalidate the other.

14 · DSAKEY_delete — free key handle

JNI 
DSA_free(getDSA(keyId));

A true one-liner. DSA_free decrements the DSA object's reference count; the object is deallocated when the count reaches zero. DSA_free(NULL) is a no-op in OpenSSL, so no explicit NULL guard is needed (though passing 0 as keyId from Java is safe).

15 · signDigest — internal sign helper

static helper static jbyteArray signDigest(JNIEnv *env, int digestNid, const unsigned char *digest, unsigned int digestLength, DSA *dsa)

The single function that performs the DSA signing operation, shared between both sign paths (pre-computed bytes and live digest context).

Buffer allocation and sizing

DSA_size(dsa) returns the maximum DER-encoded signature length. For a DSA key with a q of n bits, the maximum signature is approximately 2 × (n/8 + 1) + 8 bytes (two DER-encoded integers plus overhead). A C buffer of this size is allocated with malloc.

DSA_sign

DSA_sign(digestNid, digest, digestLength, signature, &signatureLength, dsa)

Signs the hash and writes a DER-encoded DSASignature ::= SEQUENCE { r INTEGER, s INTEGER } into the buffer. On success, signatureLength is updated to the actual encoded length (which may be less than the maximum). When digestNid == NID_undef, no DigestInfo wrapping is applied — the signature is over the raw hash bytes.

Java array creation

A Java byte array of actual length (not maximum) is created and populated via SetByteArrayRegion. The C buffer is freed before returning regardless of whether the array creation succeeded.

16 · DSAKEY_signData / verifyData — pre-computed digest path

JNI

signData

JNIEXPORT jbyteArray JNICALL Java_..._DSAKEY_1signData( JNIEnv *env, jclass cls, jlong contextId, jbyteArray digestBytes, jlong keyId)

The NONEwithDSA path — Java has already computed the hash and passes the raw bytes here. NID_undef is passed through to signDigest → DSA_sign, meaning no additional wrapping is applied.

The digest array is pinned, signDigest is called, and the array is unpinned with JNI_ABORT. The unpin happens after the sign call completes so the buffer remains valid throughout.

verifyData

JNIEXPORT jboolean JNICALL Java_..._DSAKEY_1verifyData( JNIEnv *env, jclass cls, jlong contextId, jbyteArray digestBytes, jbyteArray signatureBytes, jlong keyId)

Two arrays must be pinned. The defensive cleanup pattern handles the case where the second pin fails after the first succeeds:

if (digest == NULL || signature == NULL) {
    if (digest    != NULL) cleanupByteArray(env, digestBytes,    digest,    JNI_ABORT);
    if (signature != NULL) cleanupByteArray(env, signatureBytes, signature, JNI_ABORT);
    return JNI_FALSE;
}

DSA_verify is called with NID_undef. It returns 1 (valid), 0 (invalid), or -1 (error). All non-1 results map to JNI_FALSE — invalid signatures are not exceptions.

17 · DSAKEY_signDigestCtx / verifyDigestCtx — live digest context path

JNI

signDigestCtx

JNIEXPORT jbyteArray JNICALL Java_..._DSAKEY_1signDigestCtx( JNIEnv *env, jclass cls, jlong contextId, jlong digestCtxId, jlong pkeyId)

The SHA*withDSA path. The Java layer has fed message data to an EVP_MD_CTX via EVP_DigestUpdate; this function finalises it and signs.

  1. EVP_DigestFinal_ex(digestContext, digest, &length) — finalises the running hash into a 64-byte stack buffer (unsigned char digest[EVP_MAX_MD_SIZE]). After this call the context is exhausted.
  2. EVP_PKEY_get1_DSA(pkey) — extracts the inner DSA* from the EVP_PKEY*, incrementing the DSA refcount (hence the comment "must call DSA_free").
  3. EVP_MD_CTX_get_type(digestContext) — retrieves the NID of the digest algorithm that was active in the context (e.g. NID_sha256). This is passed to signDigest / DSA_sign directly — it avoids the length-to-NID ambiguity problem that affects OpenSSLRSAKey.c's digestLenToNid helper (where SHA-224 and SHA-512/224 both produce 28 bytes).
  4. DSA_free(dsa) — releases the get1_ reference.

verifyDigestCtx

JNIEXPORT jboolean JNICALL Java_..._DSAKEY_1verifyDigestCtx( JNIEnv *env, jclass cls, jlong contextId, jlong digestCtxId, jbyteArray signatureBytes, jint signatureLength, jlong pkeyId)

Mirror of signDigestCtx. Notable ordering: the digest is finalised into the stack buffer before the signature array is pinned. If pinning fails, the computed hash is simply discarded (it is on the stack); no cleanup is needed for it.

18 · Overall design summary

Handle types — two coexisting representations

HandleTypeCreated byFreed by
DSA* key handlejlong (DSA*)generate, createPrivateKey, createPublicKeyDSAKEY_delete
EVP_PKEY* wrapper handlejlong (EVP_PKEY*)DSAKEY_createPKeyEVP_PKEY_free (currently RSAKEY_delete)

Two sign/verify paths

PathJNI functionsJava algorithmNID passed to DSA_sign/verify
Pre-computed digestsignData / verifyDataNONEwithDSANID_undef (no wrapping)
Live digest contextsignDigestCtx / verifyDigestCtxSHA*withDSA, SHA3*withDSAFrom EVP_MD_CTX_get_type (exact NID)

DSA key lifecycle

DSAKEY_generate / createPrivateKey / createPublicKey → DSA* handle
getParameters / getPrivateKeyBytes / getPublicKeyBytes (optional export)
createPKey → EVP_PKEY* handle (for signature operations)
signData / verifyData or signDigestCtx / verifyDigestCtx
DSAKEY_delete (DSA* handle) + separate EVP_PKEY_free

In-place DER encoding pattern (shared with OpenSSLXECKey.c)

All three encode helpers (encodeDSA, encodeParameters) use the same three-step pattern: size query → NewByteArray → pin + encode + commit. This avoids OpenSSL-allocated intermediate buffers and the associated OPENSSL_free calls.

Memory ownership rules

  • DSA* from generate/create — one reference, owned by the Java handle; freed in DSAKEY_delete.
  • DSA* from EVP_PKEY_get1_DSA — caller owns this extra reference; always freed with DSA_free(dsa) at the end of signDigestCtx / verifyDigestCtx.
  • EVP_PKEY* from DSAKEY_createPKey — separate Java handle; freed independently.
  • C signature buffers from malloc — freed with free() after SetByteArrayRegion.
  • JNI arrays — always JNI_ABORT (read-only input); output bytes go via SetByteArrayRegion from a C buffer or via ReleaseByteArrayElements with flag 0 (in-place encoding).
