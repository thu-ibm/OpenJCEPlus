1 · Data Structures

Context OpenSSLContext — OpenSSLContext.h

One instance per provider instantiation. Holds the OpenSSL 3 library context and loaded providers.

FieldTypePurpose

CIPHER CipherContext — OpenSSLSymmetricCipher.h

Allocated by CIPHER_create; the opaque jlong cipherId passed through all Java calls is a cast of this pointer. Used for symmetric ciphers (CBC, CTR, ECB, …), and also re-used as the context type for GCM and CCM operations.

FieldTypePurpose
ctxEVP_CIPHER_CTX*OpenSSL cipher operation context; holds the running state for update/final
cipherconst EVP_CIPHER*Fetched algorithm object (e.g. EVP_aes_256_gcm); bound at create time, never changes
paddingint1 = PKCS#5/7 padding enabled, 0 = disabled
encryptint1 = encrypt, 0 = decrypt (stored for reinit)
blockSizeintCipher block size in bytes (1 for stream ciphers such as ChaCha20/CTR)
key / keyLenunsigned char* / intCopy of the key stored for needsReinit replay; zeroed on delete
iv / ivLenunsigned char* / intCopy of the IV stored for needsReinit replay; zeroed on delete
tagLenintAEAD tag length fixed at GCM_init / CCM_init time; validated in Final
updateCountintCounts CCM_update calls since last CCM_init; OpenSSL CCM only supports one data update per operation — a second call resets CBC-MAC silently
Security: key and iv buffers are memset(0) before free() in CIPHER_delete to prevent sensitive material lingering in heap.

2 · Symmetric Cipher Functions CIPHER

All in OpenSSLSymmetricCipher.c. Support AES (all key sizes), DES, 3DES, ChaCha20 in ECB, CBC, CTR, OFB, CFB modes.

CIPHER_create

jlong CIPHER_create(osslContextId, cipherName)

Allocates and initialises a CipherContext for the named algorithm.

  1. Validates osslContextId → resolves to OpenSSLContext
  2. mallocSafe(sizeof(CipherContext)) — zeroed allocation
  3. EVP_CIPHER_CTX_new() → stored in cipherCtx->ctx
  4. EVP_CIPHER_fetch(libctx, name, NULL) → stored in cipherCtx->cipher; fetching via libctx respects FIPS/non-FIPS provider selection
  5. Returns (jlong)cipherCtx

Returns: opaque pointer cast to jlong   Error: -1, exception pending

Note: The algorithm is permanently fixed into the context here. For GCM/CCM, the key size must match the fetched cipher (e.g. 32-byte key with AES-256-GCM) — passing a mismatched key to GCM_init will fail at EVP_CipherInit_ex.

CIPHER_init

void CIPHER_init(osslContextId, cipherId, encrypt, paddingId, key, iv)

Initialises a previously created context for encrypt or decrypt. Stores copies of key and IV for later needsReinit replay.

  1. Stores paddingId, encrypt, and blockSize (from EVP_CIPHER_get_block_size)
  2. Replaces cipherCtx->key: zeroes old buffer, mallocs new, memcpys key
  3. If IV supplied: same replacement for cipherCtx->iv
  4. Calls EVP_EncryptInit_ex or EVP_DecryptInit_ex with cipher, key, IV
  5. Calls EVP_CIPHER_CTX_set_padding: forced off for stream ciphers (blockSize==1), otherwise per paddingId
  6. Zeroes keyBytes / ivBytes before releasing JNI pinned arrays
Padding order: EVP_CIPHER_CTX_set_padding must be called after EVP_EncryptInit_ex/DecryptInit_ex — setting padding before the cipher is bound has no effect.

CIPHER_getBlockSize / CIPHER_getKeyLength / CIPHER_getIVLength

int CIPHER_getBlockSize(osslContextId, cipherId)

Thin wrappers: validate context, call EVP_CIPHER_get_block_size / EVP_CIPHER_get_key_length / EVP_CIPHER_get_iv_length on cipherCtx->cipher. For GCM contexts these return the fixed values for the fetched algorithm (e.g. AES-256-GCM key length = 32).

CIPHER_encryptUpdate

int CIPHER_encryptUpdate(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, needsReinit)

Streaming encrypt for block/stream ciphers.

  1. If needsReinit: calls EVP_EncryptInit_ex(ctx, cipher, NULL, key, iv) then re-applies padding — allows the same context to be reused for multiple independent messages without a round-trip through Java
  2. Validates input offset+length; validates output buffer ≥ inputLen + blockSize (block ciphers can buffer up to one extra block)
  3. EVP_EncryptUpdate → writes up to inputLen + blockSize - 1 bytes

Returns: bytes written   Error: -1

CIPHER_decryptUpdate

int CIPHER_decryptUpdate(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, needsReinit)

Identical structure to CIPHER_encryptUpdate using EVP_DecryptInit_ex / EVP_DecryptUpdate. Output buffer validated to ≥ inputLen + blockSize.

CIPHER_encryptFinal

int CIPHER_encryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, needsReinit)

Encrypts any remaining input bytes, then calls EVP_EncryptFinal_ex to flush the internal block buffer and append PKCS padding if enabled.

  1. Optional needsReinit re-init
  2. Output buffer validated to ≥ inputLen + blockSize (worst case: one full padding block appended)
  3. If input != NULL && inputLen > 0: EVP_EncryptUpdate for the final chunk
  4. EVP_EncryptFinal_ex — writes padding block if enabled, otherwise 0 bytes for NoPadding modes

Returns: total bytes written (update + final)   Error: -2 on Final failure

CIPHER_decryptFinal

int CIPHER_decryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, needsReinit)

Decrypts remaining ciphertext and verifies/removes padding.

  1. Optional needsReinit re-init
  2. Output buffer validated to ≥ inputLen
  3. EVP_DecryptUpdate for remaining ciphertext
  4. EVP_DecryptFinal_ex — strips padding; fails if padding is malformed
  5. On failure: inspects ERR_peek_error() — if reason is EVP_R_BAD_DECRYPT, sets message "Bad padding" (caught by the Java adapter and translated to BadPaddingException); otherwise generic error

Returns: total plaintext bytes   Error: -3 update fail, -4 final fail, -5 bad padding

CIPHER_delete

void CIPHER_delete(osslContextId, cipherId)

Frees all resources held by a CipherContext. Safe to call on a cipherId of 0 (no-op).

  1. Casts cipherId → CipherContext* (does NOT call validateCipherContext — that helper requires non-NULL ctx/cipher, which would block freeing a partially-initialised context and leak memory)
  2. memset(key, 0, keyLen); free(key) — secure wipe
  3. memset(iv, 0, ivLen); free(iv) — secure wipe
  4. EVP_CIPHER_free(cipher) — releases fetched algorithm object
  5. EVP_CIPHER_CTX_free(ctx) — releases OpenSSL cipher state
  6. free(cipherCtx)

3 · GCM Functions GCM

All in OpenSSLGCM.c. The context is a regular CipherContext created via CIPHER_create("AES-128/192/256-GCM") and cached in Java-layer ThreadLocal<GCMContextPointer> slots.

GCM_init

void GCM_init(osslContextId, cipherId, encrypt, key, iv, tagLen)

Prepares the cached GCM context for a new encrypt or decrypt operation. Called once per message.

  1. Validates tagLen in [4, 16]
  2. EVP_CIPHER_CTX_reset(ctx) — clears all state from any previous message. Critical for context reuse: without this, key/IV from the previous operation would bleed into the new one
  3. EVP_CipherInit_ex(ctx, cipher, NULL, NULL, NULL, encryptFlag) — re-arms the algorithm in the context without supplying key/IV yet
  4. If ivLen != 12: EVP_CIPHER_CTX_ctrl(EVP_CTRL_GCM_SET_IVLEN, ivLen) — non-default IV lengths must be set before the key/IV call
  5. EVP_CipherInit_ex(ctx, NULL, NULL, key, iv, encryptFlag) — installs key and IV
  6. Stores tagLen in cipherCtx->tagLen for validation in Final
IV length: NIST SP 800-38D recommends 12 bytes for optimal performance. Other lengths are supported (1–1024) but require the extra ctrl call above, which internally computes a different initial counter block via GHASH.

GCM_update

int GCM_update(osslContextId, cipherId, encrypt, input, inputOffset, inputLen, output, outputOffset, aad, aadLen)

Processes a chunk of plaintext (encrypt) or ciphertext (decrypt) and optional AAD. Used in the multi-part streaming path.

  1. If aad != null && aadLen > 0: calls processAADFromArray helper → EVP_CipherUpdate(ctx, NULL, &len, aad, aadLen) — feeding NULL output pointer into EVP signals AAD processing
  2. Validates input array offset+length and output buffer bounds (including integer-overflow guard)
  3. EVP_CipherUpdate(ctx, output+outputOffset, &outLen, input+inputOffset, inputLen)
  4. Releases pinned JNI arrays; commits output with JNI_COMMIT

Returns: bytes written to output   Error: -1

GCM streaming: GCM processes data in 16-byte AES blocks internally but EVP_CipherUpdate is byte-granular — it returns exactly inputLen bytes of ciphertext/plaintext on each call. No buffering of partial blocks occurs at the C level.

GCM_encryptFinal

int GCM_encryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, aad, aadLen, tagLen)

Completes GCM encryption, producing remaining ciphertext and appending the authentication tag.

  1. Optional AAD via processAADFromArray
  2. Overflow guard: checks (jlong)inputLen + (jlong)tagLen <= INT_MAX before computing requiredOutputSize = inputLen + tagLen
  3. Validates output buffer ≥ inputLen + tagLen
  4. If inputLen > 0: EVP_CipherUpdate for final plaintext chunk
  5. EVP_CipherFinal_ex — for GCM this is typically a no-op (0 bytes) but must be called to advance the OpenSSL state machine
  6. getAndAppendTag(EVP_CTRL_GCM_GET_TAG): EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_GET_TAG, tagLen, tag) → memcpy tag bytes after ciphertext in output buffer

Returns: total bytes written = inputLen + tagLen   Error: -1

GCM_decryptFinal

int GCM_decryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, aad, aadLen, tagLen)

Completes GCM decryption and verifies the authentication tag. The input array must be ciphertext || tag (tag is the last tagLen bytes).

  1. Optional AAD
  2. Rejects inputLen < tagLen immediately (would make requiredOutputSize negative, bypassing the buffer check)
  3. Validates output buffer ≥ inputLen - tagLen
  4. Pins input array once: pointer arithmetic extracts tag from input[inputOffset + inputLen - tagLen]
  5. EVP_CIPHER_CTX_ctrl(EVP_CTRL_GCM_SET_TAG, tagLen, tag) — must be set before the ciphertext update
  6. If actualInputLen > 0: EVP_CipherUpdate on ciphertext portion
  7. If actualInputLen == 0: processZeroLengthInput — a zero-length EVP_CipherUpdate is still required to finalise GCM internal state before tag verification
  8. EVP_CipherFinal_ex — performs tag verification; failure → sets exception OPENSSL_CIPHER_TAG_MISMATCH and returns OPENSSL_TAG_MISMATCH_ERROR (-6)

Returns: plaintext bytes written   Tag mismatch: -6 + exception   Other error: -1

Tag-before-ciphertext: EVP_CTRL_GCM_SET_TAG must be called before EVP_CipherUpdate; reversing the order causes OpenSSL to ignore the tag entirely and always report success.

4 · CCM Functions CCM

All in OpenSSLCCM.c. The context is a CipherContext created per call in the Java adapter (not cached). CCM has fundamental structural differences from GCM in the OpenSSL EVP API.

CCM_init

void CCM_init(osslContextId, cipherId, encrypt, key, iv, tagLen)

Initialises the CCM context for a single encrypt or decrypt operation.

  1. Validates tagLen in [4, 16] and must be even (CCM tag lengths are always even per NIST SP 800-38C)
  2. EVP_CIPHER_CTX_reset(ctx)
  3. EVP_CipherInit_ex(ctx, cipher, NULL, NULL, NULL, encryptFlag) — arms algorithm only
  4. EVP_CIPHER_CTX_ctrl(EVP_CTRL_CCM_SET_IVLEN, ivLen) — CCM IV must be 7–13 bytes; IV length determines the maximum message length field width
  5. EVP_CIPHER_CTX_ctrl(EVP_CTRL_CCM_SET_TAG, tagLen, NULL) — both IV length and tag length must be set before key/IV
  6. EVP_CipherInit_ex(ctx, NULL, NULL, key, iv, encryptFlag) — installs key and IV
  7. Sets cipherCtx->tagLen = tagLen and resets cipherCtx->updateCount = 0
CCM init order is strict: OpenSSL CCM requires: SET_IVLEN → SET_TAG → key+IV. Any other order results in silently wrong output or an EVP error. This differs from GCM where only IV length needs to precede key/IV.

CCM_update

int CCM_update(osslContextId, cipherId, encrypt, input, inputOffset, inputLen, output, outputOffset, aad, aadLen)

Processes data through the CCM cipher. OpenSSL CCM allows only a single data update per operation.

  1. Checks cipherCtx->updateCount > 0: throws if called more than once — a second EVP_CipherUpdate with data would re-announce the plaintext length and silently produce a wrong CBC-MAC
  2. Increments updateCount
  3. EVP_CipherUpdate(ctx, NULL, &outLen, NULL, inputLen) — announces the total plaintext length to OpenSSL; required by CCM before AAD or data
  4. Processes AAD via processAADFromArray
  5. Validates output buffer (with overflow-safe validateOutputBuffer)
  6. EVP_CipherUpdate(ctx, output, &outLen, input+offset, inputLen) — processes all plaintext/ciphertext in one call

Returns: bytes written   Error: -1

CCM length pre-announcement: GCM can process data incrementally because the authentication tag is computed online. CCM uses CBC-MAC which requires the total length to be included in the initial formatting block (B0) — that is what the EVP_CipherUpdate(NULL, NULL, inputLen) call accomplishes.

CCM_encryptFinal

int CCM_encryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, aad, aadLen, tagLen)

One-shot CCM encrypt: processes all input, appends authentication tag.

  1. Validates tagLen == cipherCtx->tagLen (mismatch would produce a silently-wrong or truncated tag since CBC-MAC was sized at init time)
  2. Announces plaintext length: EVP_CipherUpdate(NULL, NULL, inputLen)
  3. Overflow guard on inputLen + tagLen before computing requiredOutputSize
  4. Validates output buffer ≥ inputLen + tagLen
  5. Processes AAD
  6. If inputLen > 0: EVP_CipherUpdate on plaintext
  7. If inputLen == 0: calls EVP_CipherUpdate(ctx, output, &out, emptyBuf, 0) with a real (non-NULL) buffer — a NULL buffer pointer causes a crash in some OpenSSL builds; then jumps to tag retrieval (skips EVP_CipherFinal_ex which is not supported for zero-length CCM)
  8. For non-zero input: EVP_CipherFinal_ex (required by OpenSSL state machine even though it writes 0 bytes for CCM)
  9. getAndAppendTag(EVP_CTRL_CCM_GET_TAG): appends tag after ciphertext

Returns: inputLen + tagLen   Error: -1

CCM_decryptFinal

int CCM_decryptFinal(osslContextId, cipherId, input, inputOffset, inputLen, output, outputOffset, aad, aadLen, tagLen)

One-shot CCM decrypt: verifies tag, decrypts ciphertext. Input must be ciphertext || tag.

  1. Validates tagLen == cipherCtx->tagLen
  2. actualInputLen = inputLen - tagLen; rejects negative
  3. Announces plaintext length via EVP_CipherUpdate(NULL, NULL, actualInputLen)
  4. Processes AAD
  5. Validates output buffer ≥ actualInputLen
  6. Validates input offset+length
  7. extractAndSetTag(EVP_CTRL_CCM_SET_TAG): pins input array, extracts last tagLen bytes, calls EVP_CIPHER_CTX_ctrl(SET_TAG); must precede data processing
  8. If actualInputLen > 0: EVP_CipherUpdate on ciphertext
  9. If actualInputLen == 0: processZeroLengthInput
  10. EVP_CipherFinal_ex — verifies CBC-MAC; failure → exception + returns -6

Returns: plaintext bytes   Tag mismatch: -6 + exception   Other: -1

5 · Random Functions RAND

All in OpenSSLRandom.c. Two groups: basic RAND (delegates to OpenSSL's default DRBG) and extended DRBG (EVP_RAND-based HASH-DRBG with per-instance context).

DRBG_Context — internal struct

Private struct allocated by EXTRAND_create; the opaque jlong drbgContextId is a cast of this pointer.

FieldTypePurpose
ctxEVP_RAND_CTX*Instantiated HASH-DRBG context
algNamechar*Copy of the Java algorithm name passed to EXTRAND_create (e.g. "SHA256"); stored for potential future use, freed in EXTRAND_delete

RAND_nextBytes

void RAND_nextBytes(osslContextId, bytes[])

Fills bytes with cryptographically random data from the library-context-bound DRBG.

  1. Rejects null or zero-length bytes immediately
  2. validateAndGetContext → resolves OpenSSLContext (ensures FIPS provider's DRBG is used in FIPS mode)
  3. Pins bytes with GetByteArrayElements
  4. RAND_bytes_ex(context->libctx, buf, len, 0) — the libctx argument directs the call to the correct provider's DRBG
  5. On failure: releases array with JNI_ABORT, throws OpenSSLException with formatted ERR string
  6. On success: ReleaseByteArrayElements(..., 0) — copies random bytes back to Java heap
Why RAND_bytes_ex not RAND_bytes: RAND_bytes always uses the process-global default DRBG, ignoring OSSL_LIB_CTX. In FIPS mode, RAND_bytes_ex(libctx, ...) routes through the FIPS provider's DRBG as required by the FIPS boundary.

RAND_generateSeed

void RAND_generateSeed(osslContextId, bytes[])

Fills bytes with random bytes for use as seed material. Identical implementation to RAND_nextBytes — both delegate to RAND_bytes_ex.

RAND_setSeed

void RAND_setSeed(osslContextId, seed[])

Adds entropy to the global DRBG seed pool.

  1. Silently ignores null or zero-length seed
  2. Calls RAND_add(seedNative, seedLen, (double)seedLen) — feeds the process-wide entropy pool
  3. Releases seed array with JNI_ABORT (no write-back needed)
Design note: RAND_seed_ex does not exist in OpenSSL 3. The documented way to reseed a specific OSSL_LIB_CTX DRBG is via EVP_RAND_CTX reseed; for the simple case of augmenting the default pool, RAND_add (global) is the standard approach and affects all contexts.

RAND_status

jint RAND_status(osslContextId)

Returns 1 if the context-bound DRBG is ready to generate, 0 otherwise.

  1. validateAndGetContext → OpenSSLContext
  2. RAND_get0_primary(context->libctx) — retrieves the primary DRBG for this library context
  3. EVP_RAND_get_state(primary) == EVP_RAND_STATE_READY → returns 1 or 0
Why not RAND_status(): The global RAND_status() ignores OSSL_LIB_CTX and always reflects the default process context — it would return 1 even if the FIPS DRBG is not yet instantiated. Using RAND_get0_primary queries the correct per-context DRBG.

EXTRAND_create

jlong EXTRAND_create(osslContextId, algName)

Creates and instantiates an independent HASH-DRBG backed by the specified digest algorithm.

  1. Maps Java algorithm names: "SHA256" → "SHA-256", "SHA512" → "SHA-512"; others passed through
  2. EVP_RAND_fetch(context->libctx, "HASH-DRBG", NULL) — fetches the DRBG algorithm object
  3. EVP_RAND_CTX_new(rand, NULL) — creates uninstantiated context; EVP_RAND_free(rand) called immediately (context holds its own reference)
  4. Builds OSSL_PARAM array: digest = "SHA-256" (or equivalent)
  5. EVP_RAND_instantiate(ctx, 0, 0, NULL, 0, params) — initialises the DRBG with the digest selection; instantiation params cannot be set via a separate set_params call on an uninstantiated context
  6. Allocates DRBG_Context, stores ctx and a strdup of the algorithm name
  7. Returns (jlong)drbgCtx

Returns: opaque pointer cast to jlong Error: 0, exception pending

EXTRAND_nextBytes

void EXTRAND_nextBytes(osslContextId, drbgContextId, bytes[])

Generates random bytes from a specific DRBG instance.

  1. Validates drbgCtx != NULL && drbgCtx->ctx != NULL
  2. Pins bytes
  3. EVP_RAND_generate(drbgCtx->ctx, buf, len, 0, 0, NULL, 0)
  4. On failure: abort-releases array, throws OpenSSLException
  5. On success: commits bytes back to Java heap

EXTRAND_setSeed

void EXTRAND_setSeed(osslContextId, drbgContextId, seed[])

Reseeds a specific DRBG instance with the provided entropy.

  1. Validates drbgCtx; silently ignores null/empty seed
  2. EVP_RAND_reseed(drbgCtx->ctx, 0, NULL, 0, seedNative, seedLen)
  3. Releases seed array with JNI_ABORT (no write-back needed)

EXTRAND_delete

void EXTRAND_delete(osslContextId, drbgContextId)

Frees a DRBG instance. Safe to call with drbgContextId == 0 (no-op).

  1. Casts to DRBG_Context*; returns immediately if null
  2. EVP_RAND_CTX_free(drbgCtx->ctx)
  3. free(drbgCtx->algName)
  4. free(drbgCtx)

7 · Security & Safety Notes

  • Integer overflow guards — GCM_encryptFinal and CCM_encryptFinal both check (jlong)inputLen + (jlong)tagLen <= INT_MAX before computing requiredOutputSize. Without this, a near-INT_MAX inputLen would overflow a jint addition and pass a buffer-size check that should have failed.
  • Key material zeroing — CIPHER_init calls memset(keyBytes, 0) before ReleaseByteArrayElements; CIPHER_delete zeroes the stored copy. Prevents key material from persisting in native or JVM heap.
  • CCM single-update enforcement — updateCount in CCM_update prevents the silent CBC-MAC corruption that would occur if EVP_CipherUpdate is called twice with data (OpenSSL resets the MAC computation on the second length-announce).
  • Partial-init delete safety — CIPHER_delete deliberately skips validateCipherContext (which requires non-NULL ctx and cipher). This allows freeing contexts that failed midway through CIPHER_create without leaking memory.
  • GCM decrypt tag ordering — EVP_CTRL_GCM_SET_TAG must be called before the data EVP_CipherUpdate; GCM_decryptFinal pins the input array once and extracts the tag by pointer arithmetic before touching any ciphertext bytes.
  • Zero-length ciphertext — both GCM and CCM decrypt have explicit processZeroLengthInput branches to issue a dummy EVP_CipherUpdate(0 bytes) call that advances OpenSSL's state machine before EVP_CipherFinal_ex is called for tag verification.
