Overview — two C files, two APIs

Signature algorithms are split across two C files with distinct API contracts:

FilePurposeJava entry point
OpenSSLSignature.cUniversal streaming API for RSA, ECDSA, DSA, EdDSA. One context type handles all algorithms.NativeOpenSSLImplementation.SIGNATURE_*
OpenSSLRSAPSS.cDedicated RSA-PSS API, mirroring OCK's RsaPss.c contract. Separate context type, key is bound at init time not create time.NativeOpenSSLImplementation.RSAPSS_*
Both files use the same underlying OpenSSL EVP streaming functions (EVP_DigestSign* / EVP_DigestVerify*). The split exists because the Java layer's SignatureRSAPSS.java was already written against a different OCK contract (key passed at init, not at create).

1. OpenSSLSignatureContext struct OpenSSLSignature.c

The C struct that Java holds as an opaque jlong handle for all general signature operations.

typedef struct { EVP_MD_CTX* mdCtx; // Streaming digest/signature state machine EVP_PKEY* pkey; // The key (private for sign, public for verify) const EVP_MD* md; // Fetched digest algorithm (NULL for EdDSA) int mode; // SIGNATURE_MODE_SIGN (1) or VERIFY (2) int signatureSize; // Max bytes from EVP_PKEY_get_size EVP_PKEY_CTX* pkeyCtx; // Key-algorithm context (owned by mdCtx) int isEdDSA; // 1 if Ed25519/Ed448, 0 otherwise unsigned char* dataBuffer; // EdDSA accumulation buffer (NULL otherwise) size_t dataBufferSize; // Bytes currently buffered size_t dataBufferCapacity;// Allocated buffer capacity } OpenSSLSignatureContext;

Most fields apply to all algorithms. The dataBuffer / dataBufferSize / dataBufferCapacity triple only exists for EdDSA — that algorithm mandates a one-shot API (EVP_DigestSign) which requires all data at once, so updates are accumulated in this growable buffer and flushed at sign/verify time.

2. OpenSSLRSAPSSContext struct OpenSSLRSAPSS.c

The dedicated RSA-PSS context. Unlike OpenSSLSignatureContext, the key is not stored at create time — it is bound separately at signInit/verifyInit.

typedef struct { EVP_MD_CTX* mdCtx; // Streaming digest/signature context EVP_PKEY* pkey; // Bound key (NOT owned; caller owns the key) EVP_PKEY_CTX* pkeyCtx; // PSS parameter context (owned by mdCtx) const EVP_MD* md; // Message digest (owned) const EVP_MD* mgf1Md; // MGF1 digest (owned) int mode; // RSAPSS_MODE_SIGN (1) or VERIFY (2) int saltlen; // PSS salt length (stored for reset) int sigLen; // EVP_PKEY_get_size at init time char digestName[64];// For reset: re-fetch digest by name char mgf1Name[64]; // For reset: re-fetch MGF1 digest by name } OpenSSLRSAPSSContext;

Two digests (md and mgf1Md) are stored because RSA-PSS requires them independently: md hashes the message, mgf1Md drives the mask-generation function. They are usually the same algorithm, but the Java layer allows them to differ. Both are fetched at createContext time so the expensive EVP_MD_fetch call is not repeated on every sign/verify. The pkey is explicitly not owned — the caller's Java key object holds the EVP_PKEY* handle via a separate key-file context, so releaseContext must not free it.

3. SIGNATURE_create OpenSSLSignature.c high value

Creates a fully initialised OpenSSLSignatureContext ready for update calls. Performs algorithm string parsing, key loading, digest fetching, and the first EVP_DigestSignInit/EVP_DigestVerifyInit call.

if (strstr(algoName, "Ed25519") != NULL || strstr(algoName, "Ed448") != NULL) { digestName = NULL; // EdDSA has no separate digest } else if (strstr(algoName, "with") != NULL) { // Extract digest from "SHA256withRSA", "SHA256withECDSA", etc. const char* withPos = strstr(algoName, "with"); strncpy(digestBuffer, algoName, withPos - algoName); if (strcmp(digestBuffer, "NONE") == 0) digestName = NULL; // Pre-hashed data, no digest needed else digestName = digestBuffer; } else { digestName = algoName; // Bare digest name like "SHA256" }

Parses the Java algorithm string into an OpenSSL digest name. Three distinct patterns: (1) EdDSA has no configurable digest — it is baked into the curve specification. (2) "DigestwithKeyType" format — the part before "with" is the digest; if it is "NONE" the caller will feed pre-hashed data directly and no hashing is done here. (3) A bare digest name used for raw signing. This parsing avoids passing the full Java algorithm string to OpenSSL, which does not understand the "with" convention.

signatureCtx->isEdDSA = (strstr(algoName, "Ed25519") || strstr(algoName, "Ed448")) ? 1 : 0; if (signatureCtx->isEdDSA) { signatureCtx->dataBufferCapacity = 4096; signatureCtx->dataBuffer = malloc(signatureCtx->dataBufferCapacity); signatureCtx->dataBufferSize = 0; }

Pre-allocates the EdDSA data buffer at create time rather than on the first update. The 4096-byte initial capacity covers most messages without reallocation; the buffer doubles on overflow. This is structurally different from all other algorithms, which stream data through OpenSSL immediately on each update call.

pkey = d2i_PrivateKey_bio(bio, NULL); // PKCS#8 DER private key // or pkey = d2i_PUBKEY_bio(bio, NULL); // X.509 SubjectPublicKeyInfo public key

Keys arrive from Java as DER-encoded byte arrays. d2i_PrivateKey_bio decodes PKCS#8 PrivateKeyInfo (the format Java's getEncoded() produces for private keys). d2i_PUBKEY_bio decodes X.509 SubjectPublicKeyInfo (the format for public keys). Both return an EVP_PKEY* regardless of key type — RSA, EC, DSA, and EdDSA keys all go through the same path.

if (isPrivateKey) { result = EVP_DigestSignInit(signatureCtx->mdCtx, &signatureCtx->pkeyCtx, signatureCtx->md, NULL, signatureCtx->pkey); } else { result = EVP_DigestVerifyInit(signatureCtx->mdCtx, &signatureCtx->pkeyCtx, signatureCtx->md, NULL, signatureCtx->pkey); }

The first and most important OpenSSL call. EVP_DigestSignInit wires together the digest algorithm (signatureCtx->md), the key, and the message-digest context into a single streaming state machine. Passing NULL for md is valid for EdDSA — the curve dictates the hash internally. The &signatureCtx->pkeyCtx out-parameter is needed later by SIGNATURE_setPSSParams to configure RSA-PSS options. It is owned by mdCtx and freed automatically when EVP_MD_CTX_free is called.

signatureCtx->signatureSize = EVP_PKEY_get_size(signatureCtx->pkey);

Queries the maximum signature size once at create time. For RSA this is the key modulus size in bytes (e.g. 256 for RSA-2048). For ECDSA it is the maximum DER-encoded signature length. Querying here rather than at sign time avoids an awkward EVP_DigestSignFinal(ctx, NULL, &len) pattern, which for some algorithms (ECDSA) can corrupt the context state by finalising it prematurely.

4. SIGNATURE_update OpenSSLSignature.c high value

Feeds a chunk of message data into the signature context. The implementation branches on isEdDSA — the two paths are fundamentally different.

// EdDSA path: buffer the data if (signatureCtx->isEdDSA) { size_t requiredSize = signatureCtx->dataBufferSize + dataLen; if (requiredSize > signatureCtx->dataBufferCapacity) { size_t newCapacity = max(signatureCtx->dataBufferCapacity * 2, requiredSize); signatureCtx->dataBuffer = realloc(signatureCtx->dataBuffer, newCapacity); signatureCtx->dataBufferCapacity = newCapacity; } memcpy(signatureCtx->dataBuffer + signatureCtx->dataBufferSize, dataBytes + offset, dataLen); signatureCtx->dataBufferSize += dataLen; }

Ed25519 and Ed448 use the PureEdDSA construction: they hash the message internally as part of the signature algorithm, so OpenSSL does not expose a streaming update API for them. EVP_DigestSign requires all data at once. The buffer doubles on overflow to amortise realloc cost — an O(n log n) total allocation for n bytes of input.

// Non-EdDSA path: stream directly through OpenSSL if (signatureCtx->mode == SIGNATURE_MODE_SIGN) { result = EVP_DigestSignUpdate(signatureCtx->mdCtx, dataBytes + offset, dataLen); } else { result = EVP_DigestVerifyUpdate(signatureCtx->mdCtx, dataBytes + offset, dataLen); }

RSA, ECDSA, and DSA use EVP_DigestSignUpdate/EVP_DigestVerifyUpdate, which feed data into the running hash state inside mdCtx. Multiple calls are safe and each chunk is processed incrementally. Data bytes are released with JNI_ABORT immediately after — they are consumed and not needed further.

EdDSA vs streaming: The buffer accumulation in update means EdDSA memory usage grows with message size. RSA/ECDSA/DSA use constant memory regardless of message size — they hash on the fly.

5. SIGNATURE_sign OpenSSLSignature.c high value

Finalises the signing operation and returns the signature as a new Java byte array. Two code paths again — EdDSA one-shot vs streaming final.

size_t sigLen = (size_t)signatureCtx->signatureSize; unsigned char* signatureBuffer = malloc(sigLen);

Allocates a C buffer first, sized to the pre-queried maximum. The actual signature may be smaller (e.g. ECDSA produces variable-length DER), so sigLen is updated by EVP_DigestSignFinal to the actual number of bytes written. A C buffer is used rather than pinning a Java array because the actual size is not known until after the call.

// EdDSA one-shot result = EVP_DigestSign(signatureCtx->mdCtx, signatureBuffer, &sigLen, signatureCtx->dataBuffer, signatureCtx->dataBufferSize);

EVP_DigestSign performs hash+sign atomically in a single call. The accumulated dataBuffer is passed as the complete message. This is the only API EdDSA supports — there is no EVP_DigestSignUpdate / EVP_DigestSignFinal sequence for EdDSA in OpenSSL 3.

// Non-EdDSA streaming final result = EVP_DigestSignFinal(signatureCtx->mdCtx, signatureBuffer, &sigLen);

Finalises the running hash and applies the private key operation. For RSA this is modular exponentiation with PKCS#1 v1.5 or PSS padding. For ECDSA it is the (r, s) computation over the hash. The context is left in an undefined state after this call — SIGNATURE_reset must be called before reuse.

jbyteArray signatureBytes = (*env)->NewByteArray(env, (jsize)sigLen); (*env)->SetByteArrayRegion(env, signatureBytes, 0, (jsize)sigLen, (jbyte*)signatureBuffer); free(signatureBuffer);

Creates the Java output array at the actual signature size (post-final), not the maximum. Uses the copy-in pattern (SetByteArrayRegion) rather than pinning, because the C buffer is allocated and freed here rather than being a pinned Java array. The C buffer is freed immediately after the copy — key material does not linger.

6. SIGNATURE_verify OpenSSLSignature.c high value

Finalises verification. Returns 1 (valid), 0 (invalid — not an error), or -1 (error — exception pending). The three-way return value is intentional and important.

// EdDSA one-shot result = EVP_DigestVerify(signatureCtx->mdCtx, sigBytes, sigLen, signatureCtx->dataBuffer, signatureCtx->dataBufferSize); // Non-EdDSA result = EVP_DigestVerifyFinal(signatureCtx->mdCtx, sigBytes, sigLen);

Same EdDSA / streaming split as sign. The signature bytes from Java are fed directly without copying — they are read-only and released with JNI_ABORT after the call.

if (result == 1) return 1; // Valid — signature matches if (result == 0) return 0; // Invalid — signature does not match (NOT an error) // result < 0 or other: genuine error setPendingOpenSSLException(...); return -1;

OpenSSL's EVP_DigestVerifyFinal returns exactly 1 for success and 0 for a clean signature mismatch. Any other value (typically -1) signals an internal error such as a bad key or corrupted context. The Java caller (Signature.verify()) returns false for both 0 and -1 to the application, but the -1 path also throws a SignatureException. Treating 0 as an exception would break every "wrong key" or "tampered data" test.

7. SIGNATURE_reset OpenSSLSignature.c medium value

Reinitialises the context for another sign or verify operation with the same key and algorithm. Called by the Java layer after each complete sign/verify cycle.

if (signatureCtx->isEdDSA && signatureCtx->dataBuffer != NULL) { signatureCtx->dataBufferSize = 0; // Clear buffer without freeing } EVP_MD_CTX_reset(signatureCtx->mdCtx); if (signatureCtx->mode == SIGNATURE_MODE_SIGN) { EVP_DigestSignInit(signatureCtx->mdCtx, &signatureCtx->pkeyCtx, signatureCtx->md, NULL, signatureCtx->pkey); } else { EVP_DigestVerifyInit(signatureCtx->mdCtx, &signatureCtx->pkeyCtx, signatureCtx->md, NULL, signatureCtx->pkey); }

Three steps: (1) Reset the EdDSA data buffer to zero bytes but keep the allocation alive for reuse. (2) EVP_MD_CTX_reset wipes the message-digest state and releases the internal EVP_PKEY_CTX*. This call is required before EVP_DigestSignInit on an already-initialised context — attempting to re-init without reset causes an error in OpenSSL 3.x. (3) Re-init with the same key and digest that were set at create time, restoring the context to exactly the state it was in after SIGNATURE_create.

Why not reuse without reset? After EVP_DigestSignFinal the EVP_MD_CTX is in a finalised state — calling EVP_DigestSignUpdate on it returns an error. EVP_MD_CTX_reset + re-init is the only safe way to reuse the context. Skipping this was the root cause of sign-after-sign failures during early testing.

8. SIGNATURE_setPSSParams OpenSSLSignature.c medium value

Configures RSA-PSS parameters on a context that was created for RSA. Called by the Java layer after SIGNATURE_create whenever a PSS parameter spec is provided.

EVP_PKEY_CTX_set_rsa_padding(signatureCtx->pkeyCtx, RSA_PKCS1_PSS_PADDING);

Switches the RSA key context from the default PKCS#1 v1.5 padding to PSS. Must be called before the salt-length and MGF1-digest calls, because those parameters are only meaningful once PSS mode is active. The pkeyCtx pointer was captured from EVP_DigestSignInit at create time for exactly this purpose.

EVP_PKEY_CTX_set_rsa_pss_saltlen(signatureCtx->pkeyCtx, saltLen);

Sets the PSS salt length. Special sentinel values: RSA_PSS_SALTLEN_DIGEST (salt = digest length) and RSA_PSS_SALTLEN_MAX (salt as long as possible given key size). The Java layer passes these as integer constants identical to OpenSSL's — no translation needed.

const EVP_MD* mgf1Md = fetchDigestSafe(env, context, mgf1Name, ...); EVP_PKEY_CTX_set_rsa_mgf1_md(signatureCtx->pkeyCtx, mgf1Md); EVP_MD_free((EVP_MD*)mgf1Md); // Free immediately — OpenSSL makes its own copy

Fetches the MGF1 digest by name, sets it on the PSS context, then immediately frees it. This is correct: EVP_PKEY_CTX_set_rsa_mgf1_md increments the EVP_MD's internal reference count, so freeing the caller's reference does not invalidate OpenSSL's copy. Not freeing it here would leak the EVP_MD object.

Ordering constraint: setPSSParams must be called after SIGNATURE_create but before the first SIGNATURE_update. Changing PSS parameters mid-stream is not supported and would corrupt the hash state.

9. SIGNATURE_delete OpenSSLSignature.c

Frees all resources owned by the context. Called from the Java finaliser / explicit close.

EVP_MD_CTX_free(signatureCtx->mdCtx); // Also frees pkeyCtx signatureCtx->pkeyCtx = NULL; // Mark as freed (already gone) EVP_MD_free((EVP_MD*)signatureCtx->md); EVP_PKEY_free(signatureCtx->pkey); FREE_AND_NULL(signatureCtx->dataBuffer); free(signatureCtx);

Ownership is clear: mdCtx owns pkeyCtx internally, so freeing mdCtx also frees the key-algorithm context. The md (digest) was fetched with EVP_MD_fetch and must be freed explicitly with EVP_MD_free. The pkey was loaded from the Java key bytes and is fully owned here. Setting pkeyCtx = NULL after freeing mdCtx is defensive — guards against any stale pointer dereference if delete is called twice.

10. SIGNATUREEdDSA_signOneShot / verifyOneShot OpenSSLSignature.c medium value

Alternative EdDSA API that takes an EVP_PKEY* handle directly (not encoded bytes). Used by the Java EdDSASignature class which holds a native key handle rather than re-encoding keys for each operation.

/* signOneShot: two-call EVP_DigestSign pattern */ // First call: query size EVP_DigestSign(mdCtx, NULL, &sigLen, dataNat, dataLen); // Second call: actually sign unsigned char* sigBuf = malloc(sigLen); EVP_DigestSign(mdCtx, sigBuf, &sigLen, dataNat, dataLen);

Unlike SIGNATURE_sign which uses a pre-queried max size, this path calls EVP_DigestSign twice. The first call with a NULL output pointer queries the exact signature size. The second call writes the actual signature. For Ed25519 the size is always 64 bytes and both calls succeed with the same value, but using the query pattern is correct for future EdDSA variants. The mdCtx is created and destroyed within this function — no reuse.

/* verifyOneShot */ int rc = EVP_DigestVerify(mdCtx, sigNat, sigLen, dataNat, dataLen); // rc == 1: valid, rc == 0: invalid, other: error if (rc == 1) return JNI_TRUE; if (rc != 0) { setPendingOpenSSLException(...); } return JNI_FALSE;

Returns jboolean rather than jint — this API is only called by EdDSA verification which maps directly to Java's boolean verify(). The three-way OpenSSL result is collapsed into true / false / exception, consistent with how SIGNATURE_verify handles it for the streaming path.

11. RSAPSS_createContext OpenSSLRSAPSS.c high value

Allocates an OpenSSLRSAPSSContext and pre-fetches both digest algorithms. No key is bound here — key binding happens at signInit/verifyInit. This separation mirrors the OCK API contract that the Java layer was already written against.

strncpy(ctx->digestName, digestName, sizeof(ctx->digestName) - 1); strncpy(ctx->mgf1Name, mgf1Name, sizeof(ctx->mgf1Name) - 1); ctx->md = fetchDigestSafe(env, context, digestName, ...); ctx->mgf1Md = fetchDigestSafe(env, context, mgf1Name, ...);

Digest names are copied into fixed-size fields so that RSAPSS_reset can re-fetch them without requiring the Java layer to pass them again. The digests are fetched once and stored — EVP_MD_fetch is not cheap and would be wasteful to call on every sign/verify cycle.

Key difference from SIGNATURE_create: no key and no EVP_DigestSignInit at this stage. The context is in a "configured but not yet bound" state after createContext.

12. RSAPSS_signInit / verifyInit OpenSSLRSAPSS.c high value

Binds a key to the context and runs the full PSS parameter initialisation. Both delegate to the shared rsapss_init_impl helper.

static int rsapss_init_impl(JNIEnv* env, OpenSSLRSAPSSContext* ctx, EVP_PKEY* pkey, int mode, int saltlen, ...) { EVP_MD_CTX_reset(ctx->mdCtx); // Wipe any previous state ctx->pkeyCtx = NULL; // Init sign or verify EVP_DigestSignInit(ctx->mdCtx, &ctx->pkeyCtx, ctx->md, NULL, pkey); // Set PSS padding + salt length + MGF1 digest in order EVP_PKEY_CTX_set_rsa_padding(ctx->pkeyCtx, RSA_PKCS1_PSS_PADDING); EVP_PKEY_CTX_set_rsa_pss_saltlen(ctx->pkeyCtx, saltlen); if (ctx->mgf1Md != NULL) EVP_PKEY_CTX_set_rsa_mgf1_md(ctx->pkeyCtx, ctx->mgf1Md); ctx->mode = mode; ctx->pkey = pkey; // Store for reset (not owned) ctx->saltlen = saltlen; // Store for reset }

The three PSS parameter calls must come in this exact order after EVP_DigestSignInit: padding first, then salt length, then MGF1. Setting them before init has no effect because the pkeyCtx does not exist yet. The salt length and key are stored so RSAPSS_reset can reproduce this exact state without the caller providing them again.

ctx->sigLen = EVP_PKEY_get_size(pkey);

The maximum RSA signature size is the key modulus length in bytes (key size / 8). Queried here, at init time, because the key is first bound here. Stored in the context so RSAPSS_getSigLen can return it cheaply without re-querying.

13. RSAPSS_digestUpdate OpenSSLRSAPSS.c

Feeds a chunk of message data. Simpler than SIGNATURE_update — no EdDSA buffering path needed here.

if (ctx->mode == RSAPSS_MODE_SIGN) EVP_DigestSignUpdate(ctx->mdCtx, dataNat + offset, dataLen); else EVP_DigestVerifyUpdate(ctx->mdCtx, dataNat + offset, dataLen); cleanupByteArray(env, data, dataNat, JNI_ABORT);

Direct streaming update — no EdDSA special case. RSA-PSS always uses the full streaming API. Data bytes are released with JNI_ABORT: read-only, no writeback needed.

14. RSAPSS_signFinal / verifyFinal OpenSSLRSAPSS.c high value

Finalise and produce or verify the RSA-PSS signature. Unlike SIGNATURE_sign, the caller pre-allocates the output buffer.

// signFinal — caller provides buffer unsigned char* sigBuf = malloc(length); size_t sigLen = (size_t)length; EVP_DigestSignFinal(ctx->mdCtx, sigBuf, &sigLen); (*env)->SetByteArrayRegion(env, signature, 0, (jsize)sigLen, (jbyte*)sigBuf); free(sigBuf);

The Java caller (SignatureRSAPSS) calls RSAPSS_getSigLen first, allocates a Java byte array of that size, and passes it in. A C buffer is still needed as an intermediary because EVP_DigestSignFinal writes to a native unsigned char*. SetByteArrayRegion copies the result in — same copy-in pattern as key wrap. The C buffer is freed immediately after copy.

// verifyFinal — three-way result int rc = EVP_DigestVerifyFinal(ctx->mdCtx, sigNat, length); if (rc == 1) return JNI_TRUE; // Valid if (rc != 0) { setPendingOpenSSLException(...); } return JNI_FALSE; // Invalid or error

Same three-way OpenSSL result interpretation as SIGNATURE_verify: 1 = valid, 0 = invalid (normal case), anything else = error. The rc != 0 check before the false return means a -1 from OpenSSL both sets a pending exception and returns JNI_FALSE. The Java caller checks for exceptions first, so the false return value is irrelevant on the error path.

15. RSAPSS_reset / releaseContext OpenSSLRSAPSS.c

reset reinitialises for the next operation. releaseContext frees everything.

// reset rsapss_init_impl(env, ctx, ctx->pkey, ctx->mode, ctx->saltlen, fn);

One-liner because rsapss_init_impl already starts with EVP_MD_CTX_reset. The stored pkey, mode, and saltlen from the last signInit/verifyInit call are reused. This is why those values were stored at init time.

// releaseContext EVP_MD_CTX_free(ctx->mdCtx); // Frees pkeyCtx too EVP_MD_free((EVP_MD*)ctx->md); EVP_MD_free((EVP_MD*)ctx->mgf1Md); // NOTE: pkey is NOT freed — caller owns it free(ctx);

Critically, pkey is not freed here — the comment in the struct definition says "not owned; caller manages". The native key handle (EVP_PKEY*) lives in a separate key-context object managed by the Java key class. If releaseContext freed it, the key object would be left holding a dangling pointer. Both digests are freed here because they were fetched with EVP_MD_fetch inside createContext.

Lifecycle summary:
RSA-PSS: createContext → signInit/verifyInit → digestUpdate* → signFinal/verifyFinal → [reset → repeat from init] → releaseContext
General: create → [setPSSParams] → update* → sign/verify → [reset → repeat from update] → delete
