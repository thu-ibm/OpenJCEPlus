OpenSSL 4.0 Compatibility Assessment

Target Directory: src/main/native/openssl/

Status: Deprecated in OpenSSL 3.0 / Incompatible in OpenSSL 4.0

Scope: Native OpenJCEPlus cryptographic bindings

OpenSSL 3.0 formally deprecated direct access to low-level cryptographic structures (such as RSA, DSA, EC_KEY, and HMAC_CTX) in favor of opaque provider-based EVP abstractions. OpenSSL 4.0 removes these deprecated legacy APIs entirely. Below is the breakdown of non-compatible elements across the codebase.

2. Detailed File-by-File Breakdown

A. DSA Implementation (OpenSSLDSAKey.c)

  • Raw Key Lifecycle & Parameters: DSA_new(), DSA_free(), DSA_generate_parameters_ex(), DSA_generate_key() are deprecated and omitted in 4.0.
  • Serialization: d2i_DSAPrivateKey, i2d_DSAPrivateKey, d2i_DSAPublicKey, i2d_DSAPublicKey, d2i_DSAparams, i2d_DSAparams parse/serialize directly to legacy DSA structs.
  • Signing / Verifying: DSA_sign(), DSA_verify(), DSA_size() operate on raw structures rather than provider-backed EVP_PKEY contexts.
  • EVP Bridges: EVP_PKEY_set1_DSA() and EVP_PKEY_get1_DSA() are removed.

B. RSA Implementation (OpenSSLRSAKey.c)

  • Raw Key Extraction: Frequent use of EVP_PKEY_get1_RSA() and EVP_PKEY_assign_RSA() to unwrap EVP_PKEY into RSA*.
  • Cipher Operations: RSA_public_encrypt() and RSA_private_decrypt() must be migrated to EVP_PKEY_encrypt_init() / EVP_PKEY_encrypt() and EVP_PKEY_decrypt_init() / EVP_PKEY_decrypt().
  • Sign / Verify: RSA_sign() and RSA_verify() (including raw signature formatting with NID_md5_sha1) must use EVP_PKEY_sign() / EVP_PKEY_verify().

C. EC Implementation (OpenSSLECKey.c)

  • EC_KEY & EC_POINT Functions: EC_KEY_new(), EC_KEY_free(), EC_KEY_set_public_key(), EC_POINT_oct2point(), and EC_POINT_point2oct() are removed.
  • Curve & Parameter Encodings: d2i_ECPKParameters(), i2d_ECPKParameters(), and i2d_ECParameters() manipulate legacy ASN.1 curve structures directly.
  • Modern Replacement: Standardize on OSSL_PARAM key creation via EVP_PKEY_fromdata() and export via EVP_PKEY_todata() or EVP_PKEY_get_octet_string_param().

D. HMAC Utilities (OpenSSLHelpers.c / OpenSSLHelpers.h)

  • createHMACCtxSafe() utilizes legacy HMAC_CTX_new(). In OpenSSL 3.0+ / 4.0, HMAC is implemented via the EVP_MAC interface.

3. Migration Roadmap to OpenSSL 4.0

  • Step 1 (EVP_PKEY Modernization): Eliminate all EVP_PKEY_get1_* and EVP_PKEY_set1_* calls; keep keys encapsulated within EVP_PKEY*.
  • Step 2 (OSSL_PARAM Adoption): Use OSSL_PARAM builders for setting and extracting public/private key coordinates, moduli, and curve parameters.
  • Step 3 (EVP_MAC Transition): Replace legacy HMAC context helpers with EVP_MAC_fetch() and EVP_MAC_CTX.
  • Step 4 (Build Target Updates): Parameterize shared library soname versioning in makefiles.
