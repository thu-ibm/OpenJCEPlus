API split rationale — The comment explains why the file intentionally mixes OpenSSL 3 high-level (EVP_PKEY_CTX) and low-level (RSA_*) APIs:

Why low-level RSA_* for NoPadding and PKCS1? Java's RSAPrivateKeySpec keys carry only (n, e, d) — no CRT primes (p, q, dp, dq, qi). OpenSSL 3's EVP_PKEY_decrypt refuses these keys. The low-level RSA_private_decrypt performs raw m^d mod n and succeeds.
Why high-level EVP_PKEY_CTX for OAEP? OAEP is never used with plain n/d-only keys. The high-level path is used here because EVP_MD_fetch respects the caller's OSSL_LIB_CTX (review item S-2), ensuring digest lookups resolve inside the correct provider (e.g., FIPS provider).

Lines 113–137 — OAEP-only digest setup

Only entered when pad == RSA_PKCS1_OAEP_PADDING. Two EVP_MD* objects are fetched:

  • md — the OAEP hash (used to hash the label).
  • mgf — the MGF1 hash (used inside the mask generation function).

Both are fetched with the caller-supplied libctx so provider isolation is maintained. The ownership rules are subtle:

Ownership detail: After EVP_PKEY_CTX_set_rsa_oaep_md(ctx, md) and EVP_PKEY_CTX_set_rsa_mgf1_md(ctx, mgf) succeed, the EVP_PKEY_CTX takes its own internal reference. The caller must still call EVP_MD_free to release the reference obtained by EVP_MD_fetch. Line 128 frees md on failure; line 135 always frees mgf (regardless of success) — both are correct.

Lines 229–234 — Pin the Java array

getByteArrayElementsSafe pins the byte array. A separate const unsigned char* p pointer is used for the DER parse; d2i_* functions advance the pointer as they consume bytes.

Lines 241 — Standard parse: d2i_RSAPrivateKey

Attempts to parse a full PKCS#1 RSAPrivateKey structure (SEQUENCE with version, n, e, d, p, q, dp, dq, qi). For keys that have all CRT components this succeeds immediately.

Lines 243–309 — Fallback: inline DER parser for non-CRT keys

When d2i_RSAPrivateKey returns NULL (typically because e=0 in a non-CRT key from RSAPrivateKeySpec), the code manually walks the DER bytes using two inline macros:

  • DER_READ_LEN(cur, out_len) — reads a BER/DER length field at *cur, handles both short (1-byte) and long (multi-byte) encodings, advances the pointer.
  • DER_SKIP_TLV(cur) — skips one tag-length-value triplet, checking the tag is 0x02 (INTEGER), then jumping over the value.

The parser:

  1. Reads the outer SEQUENCE tag (0x30) and total length.
  2. Skips the version INTEGER.
  3. Extracts n (modulus) as a BIGNUM.
  4. Skips e (public exponent — may be 0, so it is discarded and 65537 is substituted).
  5. Extracts d (private exponent) as a BIGNUM.
  6. Builds a fresh RSA* with RSA_new() + RSA_set0_key(rsa, n, e, d).

The macros are #undefed at line 299–300 to keep the namespace clean.

Why 65537 as a fallback exponent? For m^d mod n raw decryption the public exponent is irrelevant — it is only used in encryption. Substituting 65537 satisfies OpenSSL's internal structural requirements without affecting correctness.

Lines 310–342 — Non-CRT rebuild for standard parse

Even if d2i_RSAPrivateKey succeeded, the key might have been encoded with CRT fields set to zero (e.g. from a serialised non-CRT key). Lines 315–316 read back the prime p via RSA_get0_factors. If it is NULL or zero, the RSA object is rebuilt from just (n, e, d) using a fresh RSA_new() + RSA_set0_key. This prevents OpenSSL 3 from attempting CRT operations on a key that cannot support them.

Lines 345–354 — Wrap into EVP_PKEY

EVP_PKEY_new() creates a generic key container, then EVP_PKEY_assign_RSA(pkey, rsa) assigns the RSA object and transfers ownership. After this call do not free rsa separately — it is owned by pkey. On failure RSA_free(rsa) must be called explicitly.

7 · RSAKEY_createPublicKey — import public key (lines 365–409)

JNI JNIEXPORT jlong JNICALL Java_..._RSAKEY_1createPublicKey( JNIEnv* env, jclass cls, jlong osslContextId, jbyteArray publicKeyBytes)

Straightforward compared to createPrivateKey — public keys always contain (n, e) which is unambiguous. The flow is:

  1. Pin the Java array.
  2. d2i_RSAPublicKey(NULL, &p, len) — parses PKCS#1 RSAPublicKey DER (SEQUENCE{n, e}).
  3. EVP_PKEY_assign_RSA(pkey, rsa) — wraps into a generic key handle.

No fallback DER parser is needed here because a public key always has a valid non-zero exponent.

8 · RSAKEY_getPrivateKeyBytes — export private key (lines 415–455)

JNI JNIEXPORT jbyteArray JNICALL Java_..._RSAKEY_1getPrivateKeyBytes( JNIEnv* env, jclass cls, jlong osslContextId, jlong rsaKeyId)

Serialises the private key back to PKCS#1 DER. Key steps:

  1. EVP_PKEY_get1_RSA(pkey) — extracts and bumps the reference count on the inner RSA*. The get1_ prefix means the caller owns this reference and must call RSA_free.
  2. i2d_RSAPrivateKey(rsa, &der) — encodes the key to DER; OpenSSL allocates the buffer at der.
  3. RSA_free(rsa) — releases the get1_ reference immediately after encoding.
  4. Create a Java byte[], copy the DER bytes, then OPENSSL_free(der) — note: the DER buffer was allocated by OpenSSL and must be freed with OPENSSL_free, not free().

12 · RSACIPHER_public_encrypt (lines 535–629)

JNI JNIEXPORT jint JNICALL Java_..._RSACIPHER_1public_1encrypt( JNIEnv* env, jclass cls, jlong osslContextId, jlong rsaKeyId, jint rsaPaddingId, jint mdId, jint mgf1Id, jbyteArray plaintext, jint plaintextOffset, jint plaintextLen, jbyteArray ciphertext, jint ciphertextOffset)

Encrypts with the RSA public key. Returns the output length.

Lines 566–599 — OAEP branch (paddingId == 2)

Uses the high-level EVP_PKEY_CTX API:

  1. EVP_PKEY_CTX_new_from_pkey(context->libctx, pkey, NULL) — creates an encrypt context tied to the correct library context.
  2. EVP_PKEY_encrypt_init(ctx).
  3. setCtxPadding — applies OAEP padding and both digest objects.
  4. Size query: EVP_PKEY_encrypt(ctx, NULL, &outLen, pt, ptLen) — output buffer is NULL, OpenSSL fills in outLen.
  5. Actual encrypt: EVP_PKEY_encrypt(ctx, ct + offset, &outLen, pt + offset, ptLen).
The two-call pattern is needed because OAEP ciphertext is always exactly RSA_size bytes, but using the size query is the portable, forward-compatible approach.

Lines 601–622 — NoPadding / PKCS1 branch

Uses the low-level path: EVP_PKEY_get1_RSA(pkey) extracts the inner RSA*, then RSA_public_encrypt(ptLen, pt+off, ct+off, rsa, pad) performs the operation. RSA_free(rsa) releases the get1_ reference immediately after use.

Lines 624–628 — Cleanup label

The done: label releases pinned arrays. Note the asymmetry: the plaintext is unpinned with JNI_ABORT (read-only, no write-back) while the ciphertext is unpinned with 0 (JNI_COMMIT — the output bytes must be written back to the Java array).

13 · RSACIPHER_private_encrypt (lines 635–687)

Encrypts with the private key — used for the "NONEwithRSA" and "RSAforSSL" sign paths where the Java layer performs its own DigestInfo wrapping and passes the result here as raw bytes.

Always uses RSA_private_encrypt(ptLen, pt, ct, rsa, pad) — no OAEP branch because OAEP is never used with private-key encryption. The convertKey parameter is accepted for API symmetry but not used (OpenSSL keys loaded from DER are always normalised).

18 · RSAKEY_verifyDataWithRSA (lines 941–987)

Verifies a PKCS#1 v1.5 signature against a pre-computed digest. Returns JNI_TRUE / JNI_FALSE.

Lines 957–966 — Pin both arrays

The digest and signature arrays are pinned sequentially. If pinning the signature fails after pinning the digest, the digest pin is released before returning.

Lines 978–980 — RSA_verify

int r = RSA_verify(nid, digestNat, digestBytesLen, sigNat, sigBytesLen, rsa);

RSA_verify applies the RSA public-key operation, strips PKCS#1 padding, unwraps the DigestInfo, and compares the embedded hash to the provided digestNat. Returns 1 on match, 0 on mismatch. Unlike SIGNATURE_verify there is no separate error code — any non-1 result maps to JNI_FALSE.

20 · RSAKEY_signDigestCtx (lines 1008–1080)

Alternative sign path: instead of receiving pre-computed digest bytes, it receives a live EVP_MD_CTX* (a digest context that has already absorbed all message data via EVP_DigestUpdate calls). It finalises the hash internally and then signs.

EVP_MD_CTX_get_type(mdCtx) returns the NID of the digest algorithm active in the context. EVP_MD_CTX_get_size(mdCtx) returns the digest output length in bytes. Both are needed before finalising.

EVP_DigestFinal_ex(mdCtx, hash, &hashLen) completes the hash computation into a stack-allocated unsigned char hash[EVP_MAX_MD_SIZE] buffer (64 bytes max). After this call the mdCtx is exhausted but remains alive — the caller is responsible for freeing it.

Same EVP_PKEY_get1_RSA + RSA_size + RSA_sign(nid, hash, hashLen, sig, &outLen, rsa) pattern as signDataWithRSA. The NID came from the context itself rather than from a length-to-NID mapping, so it is always exact.

21 · RSAKEY_verifyDigestCtx (lines 1086–1139)

JNI JNIEXPORT jboolean JNICALL Java_..._RSAKEY_1verifyDigestCtx( JNIEnv* env, jclass cls, jlong osslContextId, jlong digestCtxId, jbyteArray sigBytes, jint sigBytesLen, jlong rsaPubKeyId)

Mirror of signDigestCtx for verification. Finalises the live digest context then calls RSA_verify(nid, hash, hashLen, sigNat, sigBytesLen, rsa). Returns JNI_TRUE / JNI_FALSE.

22 · RSASSL_SIGNATURE_sign (lines 1149–1212)

JNI JNIEXPORT jbyteArray JNICALL Java_..._RSASSL_1SIGNATURE_1sign( JNIEnv* env, jclass cls, jlong osslContextId, jbyteArray digest, jlong rsaKeyId)

Signs the legacy SSL 3.0 / TLS 1.0 combined digest (MD5 + SHA-1 concatenated = 36 bytes). The NID is hardcoded as NID_md5_sha1 rather than being derived from the digest length.

Historical context: Before TLS 1.2, the SSL handshake signature was computed over a 36-byte value: MD5(msg) ‖ SHA-1(msg). RSA_sign(NID_md5_sha1, ...) applies this specific DigestInfo encoding to match what ICC's ICC_RSA_sign produces.

Flow is identical to signDataWithRSA except for the hardcoded NID.

23 · RSASSL_SIGNATURE_verify (lines 1223–1270)

JNI JNIEXPORT jboolean JNICALL Java_..._RSASSL_1SIGNATURE_1verify( JNIEnv* env, jclass cls, jlong osslContextId, jbyteArray digest, jlong rsaKeyId, jbyteArray sigBytes, jboolean convert)

Verifies the legacy SSL MD5+SHA-1 signature. Hardcoded NID_md5_sha1. The convert parameter is accepted but intentionally unused — the comment notes that OpenSSL RSA keys loaded from DER are always normalised, so no encoding conversion is needed.

Pins both digest and sigBytes, extracts RSA*, calls RSA_verify(NID_md5_sha1, ...), then releases everything before returning JNI_TRUE / JNI_FALSE.

Memory ownership rules

  • EVP_PKEY* — one reference per handle; freed only in RSAKEY_delete.
  • RSA* from EVP_PKEY_get1_RSA — caller owns the reference; freed with RSA_free immediately after each use.
  • RSA* assigned via EVP_PKEY_assign_RSA — ownership transferred to EVP_PKEY; never free separately.
  • DER buffers from i2d_* — allocated by OpenSSL; must be freed with OPENSSL_free, not free().
  • Signature buffers from malloc — freed with free() after copying to Java array.
  • EVP_MD* from EVP_MD_fetch — freed with EVP_MD_free after setting on a CTX.
  • JNI input arrays — unpinned with JNI_ABORT; output arrays with 0 (commit).
