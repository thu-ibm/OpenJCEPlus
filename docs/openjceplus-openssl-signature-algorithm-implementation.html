Signature Algorithm Implementation

OpenJCEPlus · OpenSSL backend · branch thu/openssl-aes

Introduction

A digital signature is a cryptographic mechanism that provides three security guarantees simultaneously: authenticity (the data came from the holder of a specific private key), integrity (the data has not been altered since it was signed), and non-repudiation (the signer cannot later deny having signed it). The process always involves two complementary operations:

  • Sign — the private key holder computes a signature over a message (or its digest), producing a compact byte string that accompanies the data.
  • Verify — any party with the corresponding public key can check that the signature is valid for the given message.

OpenJCEPlus exposes digital signatures through the standard Java Cryptography Architecture (JCA) java.security.Signature API. The OpenSSL backend implements the following algorithm families:

FamilyStandardKey typeTypical use
RSA PKCS#1 v1.5 (RFC 8017) RSA public/private key pair TLS certificates, code signing, email (S/MIME)
RSA-PSS RSASSA-PSS (RFC 8017 §8.1) RSA public/private key pair Preferred RSA signature scheme; stronger security proof than PKCS#1 v1.5
DSA FIPS 186-4 / 186-5 DSA public/private key pair (DL group) Legacy government and enterprise PKI
ECDSA FIPS 186-4 / SEC1 EC public/private key pair (named curve) TLS 1.3, code signing, modern PKI; smaller keys than RSA
EdDSA RFC 8032 (Ed25519, Ed448) Edwards-curve key pair SSH, TLS 1.3, high-performance signing; deterministic, no random nonce

How a signature algorithm works

Every family follows the same high-level structure, but differs in how the digest and the signing primitive interact:

Typical sign flow — SHA256withRSA as an example
1
Digest — SHA-256 is computed over the message bytes (incrementally via update() calls).
2
DigestInfo wrap — the raw digest is prefixed with an ASN.1 DigestInfo structure identifying the hash algorithm.
3
PKCS#1 pad — the padded value is extended to the RSA modulus length using PKCS#1 v1.5 type-1 padding.
4
RSA private-key operation — the padded value is raised to the private exponent modulo n, producing the signature.

Verification reverses the process: the public exponent recovers the padded DigestInfo, the receiver independently digests the message, and the two digests are compared.

Digest algorithms

All hash-based signature families (RSA, DSA, ECDSA) support both SHA-2 and SHA-3 digest variants. EdDSA uses an internal hash that is fixed per curve and is not configurable: Ed25519 uses SHA-512 internally; Ed448 uses SHAKE256.

1 · Architecture Overview

All signature algorithms follow a four-layer delegation chain. The entry point is always a standard JCE SignatureSpi subclass. State is maintained in Java base helpers, which call the OpenSSL adapter, which in turn dispatches to native C functions.

Java / JCE RSASignature, DSASignature, ECDSASignature, EdDSASignature, RSAPSSSignature …
extends SignatureSpi — converts JCA keys, calls base helpers
↓
Base helpers base.Signature, base.SignatureRSAPSS, base.SignatureEdDSA, base.SignatureDSANONE, base.SignatureRSASSL
maintain native context handles, own the update/sign/verify lifecycle
↓
OpenSSL Adapter NativeOpenSSLAdapter — delegates to NativeOpenSSLImplementation (static native methods)
dispatches by PKEY type (RSA/DSA/EC) using PKEY_getBaseId
↓
Native C (OpenSSL 3.x) OpenSSLSignature.c · OpenSSLRSAPSS.c · OpenSSLRSAKey.c · OpenSSLDSAKey.c · OpenSSLECKey.c
calls EVP_DigestSign*, EVP_DigestVerify*, DSA_sign/verify, RSA_sign/verify
Key routing — The generic SIGNATURE_sign / SIGNATURE_verify path in NativeOpenSSLAdapter inspects the PKEY type with PKEY_getBaseId() and routes to the algorithm-specific native path: RSA → RSAKEY_signDigestCtx, DSA → DSAKEY_signDigestCtx, EC → finalizes digest then calls ECKEY_signDatawithECDSA.

Native implementation — OpenSSLRSAKey.c

RSAKEY_signDigestCtx finalizes the live EVP_MD_CTX (via EVP_DigestFinal_ex), wraps the digest in a DigestInfo ASN.1 structure, then applies PKCS#1 v1.5 signature via RSA_sign or equivalent. RSAKEY_verifyDigestCtx mirrors the process with RSA_verify.

NONEwithRSA Pre-hashed · raw RSA with PKCS#1 padding
Pre-hashed

RSASignatureNONE buffers the entire input in a ByteArrayOutputStream, then encrypts with RSACipher using RSAPadding.PKCS1Padding. Signing calls privateEncrypt; verification calls publicDecrypt and compares the result byte-by-byte with the accumulated input.

No separate digest operation — the caller is expected to supply pre-digested data.

RSAforSSL MD5+SHA-1 combined · SSL/TLS handshake legacy
Pre-hashed

Two parallel implementations exist:

RSASignatureSSL_I2
(preferred)		 Buffers input → base.SignatureRSASSL → native RSASSL_SIGNATURE_sign(digest, rsaKeyId)

Native — OpenSSLRSAKey.c

/* Signing */
RSA* rsa = EVP_PKEY_get1_RSA(privKey);
RSA_sign(NID_md5_sha1, digest, digestLen, sigBuf, &outLen, rsa);

/* Verification */
RSA* rsa = EVP_PKEY_get1_RSA(pubKey);
RSA_verify(NID_md5_sha1, digest, digestLen, sig, sigLen, rsa);

NID_md5_sha1 is the concatenation of MD5 and SHA-1 hashes (36 bytes total), which is the digest used in TLS 1.0/1.1 ServerKeyExchange messages.

3 · RSA-PSS (RSASSA-PSS)

RSAPSS / RSASSA-PSS Probabilistic Signature Scheme · configurable salt & MGF1
Streaming

Java class hierarchy

RSAPSSSignature (extends SignatureSpi)
  ↓ owns
  base.SignatureRSAPSS
    ↓ holds native handle (rsaPssId → OpenSSLRSAPSSContext*)
    ↓ calls
    NativeOpenSSLAdapter.RSAPSS_*

Parameters

Configured via PSSParameterSpec. Defaults to SHA-256 / MGF1(SHA-256) / salt=32. All four components are configurable:

  • Message digest algorithm (e.g., SHA-256)
  • MGF1 digest algorithm (may differ from message digest)
  • Salt length (bytes)
  • Trailer field (always 1 in practice)

Native context lifecycle

/* Context creation */
RSAPSS_createContext(digestAlgo, mgf1SpecAlgo)
  → allocates OpenSSLRSAPSSContext
  → EVP_MD_fetch(digestAlgo)
  → EVP_MD_fetch(mgf1SpecAlgo)
  → EVP_MD_CTX_new()

/* Sign init */
RSAPSS_signInit(rsaPssId, privKeyId, saltlen, convert)
  → EVP_DigestSignInit(mdCtx, &pkeyCtx, md, NULL, privKey)
  → EVP_PKEY_CTX_set_rsa_padding(pkeyCtx, RSA_PKCS1_PSS_PADDING)
  → EVP_PKEY_CTX_set_rsa_pss_saltlen(pkeyCtx, saltlen)
  → EVP_PKEY_CTX_set_rsa_mgf1_md(pkeyCtx, mgf1Md)

/* Streaming update */
RSAPSS_digestUpdate(rsaPssId, data, offset, length)
  → EVP_DigestSignUpdate(mdCtx, data, length)   // sign mode
  → EVP_DigestVerifyUpdate(mdCtx, data, length) // verify mode

/* Sign final */
RSAPSS_signFinal(rsaPssId, outBuf, sigLen)
  → EVP_DigestSignFinal(mdCtx, sigBuf, &sigLen)

/* Verify final */
RSAPSS_verifyFinal(rsaPssId, sigBytes, sigLen)
  → EVP_DigestVerifyFinal(mdCtx, sig, sigLen)
  // 1=valid, 0=invalid sig, other=error

/* Reset */
RSAPSS_reset(rsaPssId)
  → re-runs rsapss_init_impl with same key/mode/saltlen

/* Release */
RSAPSS_releaseContext(rsaPssId)
  → EVP_MD_CTX_free + EVP_MD_free + free(ctx)
Note: The PSS context does not own the EVP_PKEY. The caller (Java) owns the key; the context only holds a borrowed reference. The EVP_PKEY_CTX within the EVP_MD_CTX is managed by OpenSSL.

4 · DSA Signatures

SHA*withDSA family Streaming digest · prehash then DSA_sign
Streaming

Supported algorithms

SHA1withDSA, SHA224withDSA, SHA256withDSA, SHA384withDSA, SHA512withDSA, SHA3-224withDSA … SHA3-512withDSA

FIPS mode restriction

DSA signing is disabled in FIPS mode — an exception is thrown from DSASignature.engineInitSign. Verification is still allowed.

Native — OpenSSLDSAKey.c

/* Digest-context sign */
DSAKEY_signDigestCtx(osslContextId, digestId, pkeyId)

  → DSA* dsa = EVP_PKEY_get1_DSA(pkey)
  → int nid  = EVP_MD_CTX_get_type(digestCtx)
  → DSA_sign(nid, digest, digestLen, sig, &sigLen, dsa)

/* Digest-context verify */
DSAKEY_verifyDigestCtx(osslContextId, digestId, sigBytes, sigLen, pkeyId)
  → EVP_DigestFinal_ex(digestCtx, digest, &len)
  → DSA_verify(nid, digest, digestLen, sig, sigLen, dsa)

5 · ECDSA Signatures

SHA*withECDSA family Streaming digest · digest finalized then signed via generic context
Streaming

Supported algorithms

SHA1withECDSA, SHA224withECDSA, SHA256withECDSA, SHA384withECDSA, SHA512withECDSA, SHA3-224withECDSA … SHA3-512withECDSA

Two-phase signing flow

Unlike RSA and DSA, ECDSA in the OpenSSL adapter does not call a single signDigestCtx function. Instead it finalizes the digest in Java-space and then creates a temporary generic NONEwithECDSA native context: 

/* Adapter — SIGNATURE_sign with EC key */

// 1. Finalize the running digest
byte[] digestBytes = DIGEST_digest(digestId);

// 2. Get private key bytes (SEC1 DER)
byte[] sec1 = ECKEY_getPrivateKeyBytes(pkeyId);

// 3. Create a one-shot NONEwithECDSA context
long sigCtx = SIGNATURE_create(sec1, "NONEwithECDSA", mode=0 /*sign*/);

// 4. Feed the digest as "data"
SIGNATURE_update(sigCtx, digestBytes, 0, digestBytes.length);

// 5. Produce the signature
byte[] sig = SIGNATURE_sign(sigCtx);

// 6. Release
SIGNATURE_delete(sigCtx);

Verification — SPKI reconstruction

// 1. Get raw EC public point (04 x y…)
byte[] point = ECKEY_getPublicKeyBytes(pkeyId);

// 2. Get ECParameters DER
byte[] params = ECKEY_getParameters(pkeyId);

// 3. Build SubjectPublicKeyInfo (SPKI) DER manually
//    in NativeOpenSSLAdapter.buildSPKIforEC(...)

// 4. Create NONEwithECDSA verify context
long sigCtx = SIGNATURE_create(spki, "NONEwithECDSA", mode=1 /*verify*/);

// 5. Update with digest bytes
SIGNATURE_update(sigCtx, digestBytes, 0, digestBytes.length);

// 6. Verify
boolean ok = SIGNATURE_verify(sigCtx, sigBytes);
SIGNATURE_delete(sigCtx);
NONEwithECDSA Pre-hashed · buffers input · ASN.1 re-encoding
Pre-hashed

DatawithECDSA buffers the entire message. On signing, it calls ECKey.signDatawithECDSA which uses the generic NONEwithECDSA native context path. The returned ECDSA ASN.1 DER is re-parsed to remove any trailing zero padding that some OpenSSL versions may add: 

// Strip provider-specific padding from DER SEQUENCE { INTEGER r, INTEGER s }
DerValue[] integers = in.getSequence(2);
// re-encode canonically

6 · EdDSA (Ed25519 / Ed448)

EdDSA / Ed25519 / Ed448 One-shot · no separate digest · internally deterministic
One-shot

Java class hierarchy

EdDSASignature (abstract, extends SignatureSpi)
  ├─ EdDSASignature.Ed25519
  ├─ EdDSASignature.Ed448
  └─ EdDSASignature.EdDSA
       ↓ owns
       base.SignatureEdDSA (holds EVP_PKEY* handle as pkeyId)
         ↓ calls
         NativeOpenSSLAdapter.SIGNATUREEdDSA_signOneShot / verifyOneShot

Message buffering

Although EdDSA is fundamentally one-shot, JCA's SignatureSpi requires engineUpdate support. EdDSASignature solves this by accumulating all update bytes in a ByteArrayOutputStream and passing the complete message to native in a single call.

Parameter restrictions

Ed25519/Ed448 in this implementation are pure (non-prehashed) and context-free:

  • Pre-hash mode (isPrehash() = true) → InvalidAlgorithmParameterException
  • Non-empty context string → InvalidAlgorithmParameterException

Native — OpenSSLSignature.c

/* One-shot sign — SIGNATUREEdDSA_signOneShot */
EVP_MD_CTX* mdCtx = EVP_MD_CTX_new();
EVP_DigestSignInit(mdCtx, &pkeyCtx, NULL /*no md*/, NULL, pkey);
EVP_DigestSign(mdCtx, NULL, &sigLen, data, dataLen);  // get length
EVP_DigestSign(mdCtx, sigBuf, &sigLen, data, dataLen); // produce sig
EVP_MD_CTX_free(mdCtx);

/* One-shot verify — SIGNATUREEdDSA_verifyOneShot */
EVP_MD_CTX* mdCtx = EVP_MD_CTX_new();
EVP_DigestVerifyInit(mdCtx, &pkeyCtx, NULL, NULL, pkey);
int rc = EVP_DigestVerify(mdCtx, sig, sigLen, data, dataLen);
EVP_MD_CTX_free(mdCtx); // returns 1=ok, 0=bad sig, other=error

Generic context path (alternative)

EdDSA can also be invoked through the generic SIGNATURE_create context (passing "Ed25519" or "Ed448" as the algorithm). In that path, OpenSSLSignature.c detects isEdDSA=1 and accumulates update bytes in a native heap buffer, then calls EVP_DigestSign one-shot at the end.

7 · Generic Native Signature Context

OpenSSLSignature.c implements a reusable low-level context (OpenSSLSignatureContext) that all algorithm families can use. It is the C-side counterpart of the SIGNATURE_create / update / sign / verify / reset / delete Java API. 

typedef struct {
    EVP_MD_CTX*   mdCtx;            // digest+sign context
    EVP_PKEY*     pkey;             // loaded from DER bytes
    const EVP_MD* md;               // fetched digest algorithm
    int           mode;             // 0=sign, 1=verify
    int           signatureSize;    // EVP_PKEY_get_size()
    EVP_PKEY_CTX* pkeyCtx;          // for PSS param configuration
    int           isEdDSA;          // 1 if Ed25519/Ed448
    unsigned char* dataBuffer;      // accumulated EdDSA message
    size_t         dataBufferSize;
    size_t         dataBufferCapacity;
} OpenSSLSignatureContext;

Context creation — SIGNATURE_create

Parses the algorithm name string and sets up the context:

Algorithm tokenAction
SHA256withRSA, SHA256withECDSA, etc.Parse digest prefix; fetch MD with EVP_MD_fetch
NONEwith*Set digestName=NULL; no digest fetch
Ed25519, Ed448Set isEdDSA=1; no digest; allocate data buffer

Key loading:

  • mode 0 (sign): d2i_PrivateKey_bio — PKCS#8 private key DER
  • mode 1 (verify): d2i_PUBKEY_bio — SubjectPublicKeyInfo DER

After loading, initializes with EVP_DigestSignInit or EVP_DigestVerifyInit.

Reset — SIGNATURE_reset

Calls EVP_MD_CTX_reset then re-runs EVP_DigestSignInit / EVP_DigestVerifyInit with the same key and digest. This lets the same native context be reused for multiple operations without allocating a new one.

9 · Streaming vs One-shot vs Pre-hashed

Streaming digest model

Used by SHA*withRSA, SHA*withDSA, SHA*withECDSA, RSAPSS.

// Java / JCA caller
sig.initSign(privateKey);
sig.update(data, 0, data.length);   // can call multiple times
byte[] signature = sig.sign();

// Internal flow:
//   update → digest.update → DIGEST_update(digestCtx, data)
//   sign   → SIGNATURE_sign(digestCtx, pkeyId)
//          → finalize digest in native, then sign with key

The digest context (digestId) is a long-lived native handle. The signature operation finalizes it, which exhausts it — the digest is reset after each sign or verify call so the context is ready for reuse.

One-shot model (EdDSA)

Used only by EdDSA algorithms.

// Java / JCA caller
sig.initSign(privateKey);
sig.update(part1);   // buffered in ByteArrayOutputStream
sig.update(part2);   // buffered
byte[] signature = sig.sign();

// Internal flow:
//   sign → concat all buffered parts → SIGNATUREEdDSA_signOneShot(pkeyId, allData)
//         → EVP_DigestSign(mdCtx, NULL, &len, data, dataLen)  // get length
//         → EVP_DigestSign(mdCtx, sig, &len, data, dataLen)   // produce sig

EdDSA is inherently one-shot because the algorithm internally hashes the message with a specific scheme (SHA-512 for Ed25519). There is no way to feed it incrementally to OpenSSL; the complete message must be supplied in one call.

Pre-hashed model

Used by NONEwith* algorithms and RSAforSSL.

// Java / JCA caller — caller provides pre-digested data
sig.initSign(privateKey);
sig.update(digestBytes);  // exactly the digest, not the message
byte[] signature = sig.sign();

// Internal flow:
//   sign → collect digestBytes → DSANONE_SIGNATURE_sign(digestBytes, dsaKeyId)
//         → DSA_sign(NID_undef, digest, 20, sig, &sigLen, dsa)

No digest context is used. The native function receives the raw digest bytes directly.
