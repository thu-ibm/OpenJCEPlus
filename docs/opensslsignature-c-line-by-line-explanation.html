1 · File header & includes (lines 1–41)

Lines 1–7 — Copyright block

Standard IBM copyright notice. Marks the file as free software under the IBM Classpath licence, identical to the rest of the project.

Lines 9–27 — Doxygen file-level comment

Describes the file's purpose at a high level. Four points are worth noting:

  • EVP interface — all cryptographic operations go through OpenSSL's high-level EVP_* API rather than low-level RSA/ECDSA/DSA primitives. This means algorithm selection is string-driven and works equally with the FIPS provider.
  • Streaming model — callers may call update multiple times before a single sign or verify.
  • EdDSA exception — Ed25519/Ed448 do not support incremental updates in OpenSSL 3.x, so the file manually buffers data and uses a one-shot API.
  • FIPS mode — all operations validate a fipsFlag parameter on every call to select the correct OSSL_LIB_CTX.

Lines 255–276 — EdDSA buffer initialisation

When isEdDSA == 1, a 4096-byte heap buffer is allocated immediately. If malloc fails here, the partially-built struct is freed before returning 0.

Why buffer at all? OpenSSL 3.x's Ed25519/Ed448 implementation does not support EVP_DigestSignUpdate/EVP_DigestVerifyUpdate; all data must be passed in a single EVP_DigestSign/EVP_DigestVerify call. The buffer accumulates incremental updates so the Java streaming API still works.

Lines 279–285 — Key loading

Calls loadKeyFromBytes (section 4). On failure the partially-built struct and the EdDSA buffer are freed via the FREE_AND_NULL macro before returning.

Lines 288–301 — Digest algorithm fetch

fetchDigestSafe(env, context, digestName, ...) calls EVP_MD_fetch on the library context. The returned EVP_MD* is a reference-counted OpenSSL object; the caller is responsible for EVP_MD_free()ing it when done. If digestName is NULL (EdDSA, NONE-digest), signatureCtx->md is left NULL — OpenSSL accepts NULL for the digest in EVP_DigestSignInit for EdDSA.

Lines 303–314 — EVP_MD_CTX creation

createMDCtxSafe calls EVP_MD_CTX_new(). The context manages all digest + signing state going forward. On failure the already-acquired key and digest objects are freed before returning.

Lines 318–338 — Sign/Verify initialisation

EVP_DigestSignInit(signatureCtx->mdCtx, &signatureCtx->pkeyCtx,
                   signatureCtx->md, NULL, signatureCtx->pkey);

This is the pivotal call. It:

  1. Associates the digest algorithm with the context.
  2. Associates the private/public key.
  3. Populates pkeyCtx (the inner EVP_PKEY_CTX*), which is needed later by SIGNATURE_setPSSParams.
  4. The 4th argument (NULL) is for an ENGINE*; deprecated in OpenSSL 3 but kept for compatibility.

On failure a full cleanup (mdCtx, md, pkey, dataBuffer, struct) is performed before throwing OPENSSL_SIGNATURE_INIT_FAILED.

Lines 344 — Pre-compute signature size

EVP_PKEY_get_size(pkey) returns the maximum possible DER-encoded signature size for the key. For ECDSA this is an upper bound (actual DER size varies); for RSA it is exact. Stored in signatureCtx->signatureSize so SIGNATURE_sign can allocate a buffer without a separate OpenSSL query that would consume the streaming context state.

Lines 353–355 — Return

The struct pointer is cast through intptr_t to jlong and returned. Java stores this as a long field and passes it back as signatureId on every subsequent call.

6 · SIGNATURE_create — JNI entry point (lines 358–364)

JNI JNIEXPORT jlong JNICALL Java_..._SIGNATURE_1create(JNIEnv* env, jclass cls, jint fipsFlag, jbyteArray keyBytes, jint keyLength, jstring algorithm, jint mode)

A thin shim. The Java API includes a keyLength parameter (a leftover from an earlier design where raw key lengths were passed separately). The native layer has no use for it — the DER encoding is self-describing — so it is explicitly cast away with (void)keyLength to suppress compiler warnings, and the call is forwarded to signature_create_impl.

7 · SIGNATURE_update — streaming data feed (lines 369–489)

JNI JNIEXPORT jint JNICALL Java_..._SIGNATURE_1update(JNIEnv* env, jclass cls, jint fipsFlag, jlong signatureId, jbyteArray data, jint offset, jint dataLen)

Called once per chunk of data. Returns 1 on success, -1 on error.

Lines 377–381 — Context validation

Standard call to validateSignatureContext. Returns -1 (not 0) on failure so Java callers can distinguish "no data processed" from "success".

Lines 384–394 — Input guards

NULL check on data array. Zero-length data returns 1 immediately — a no-op is valid. validateOffsetAndLength checks that offset + dataLen <= arrayLen to prevent out-of-bounds reads.

Lines 403–409 — Pin Java array

getByteArrayElementsSafe pins the byte array. The offset is applied in later calls as dataBytes + offset; the array is not sliced.

Lines 420–461 — EdDSA branch: buffer the data

When isEdDSA == 1, data is appended to the heap buffer:

  1. Capacity check: if dataBufferSize + dataLen > dataBufferCapacity, call realloc to at least double the buffer.
  2. Double-or-fit growth: new capacity = max(current × 2, required). This amortises realloc calls to O(log n) over the lifetime.
  3. Copy: memcpy the incoming bytes starting at the current write position.
  4. Unpin the Java array with JNI_ABORT (no write-back needed).

Lines 462–484 — Non-EdDSA branch: streaming update

Calls either EVP_DigestSignUpdate or EVP_DigestVerifyUpdate depending on signatureCtx->mode. Both functions feed data into the running hash inside mdCtx and return 1 on success.

The data pointer passed to OpenSSL is (unsigned char*)(dataBytes + offset) — the offset is applied here, not when pinning the array.

8 · SIGNATURE_sign — finalize & return bytes (lines 494–655)

JNI JNIEXPORT jbyteArray JNICALL Java_..._SIGNATURE_1sign(JNIEnv* env, jclass cls, jint fipsFlag, jlong signatureId)

Takes no data — all data was fed via update. Produces and returns a Java byte[] containing the signature.

Lines 500–511 — Validation & mode check

In addition to validateSignatureContext, the function explicitly checks mode == SIGNATURE_MODE_SIGN. Calling sign on a verify-context is a programming error; the exception OPENSSL_SIGNATURE_INVALID is thrown.

Lines 514–536 — Allocate C output buffer

Uses the pre-computed signatureCtx->signatureSize to size the buffer. The comment explains why this is preferred over calling EVP_DigestSignFinal(mdCtx, NULL, &sigLen): that two-phase approach can mutate the context state in some OpenSSL versions, breaking the streaming model.

Lines 540–563 — EdDSA one-shot path

Calls EVP_DigestSign(mdCtx, sigBuf, &sigLen, dataBuffer, dataBufferSize). This is the single call that performs hash + sign atomically over the entire buffered message.

Lines 566–586 — Non-EdDSA finalization

EVP_DigestSignFinal(mdCtx, sigBuf, &sigLen) finalises the running hash and produces the signature. After this call, sigLen holds the actual number of bytes written (which may be less than the allocated signatureSize for variable-length formats like ECDSA DER).

Lines 608–642 — Java array creation and copy

A new Java byte array of actual size (sigLen, not max size) is created with NewByteArray, then populated with SetByteArrayRegion. The C buffer is freed immediately after the copy. After both calls an ExceptionCheck guards against the rare case where SetByteArrayRegion throws an ArrayIndexOutOfBoundsException.

Why allocate a C buffer first instead of a Java array? NewByteArray returns a GC-managed object. Passing its pinned address directly to EVP_DigestSignFinal is unsafe because the GC could move the object. Using a C buffer avoids this entirely.

Line 650 — Context not reset

The comment notes that the context is intentionally not reset after signing. The Java layer calls SIGNATURE_reset explicitly if it wants to reuse the context, or SIGNATURE_delete to free it.

Null check and length check. An empty signature is always invalid but should be caught here before calling OpenSSL, as EVP_DigestVerifyFinal with length 0 has undefined behaviour.

The signature bytes are pinned. Unlike the data buffer, these are read-only and will be unpinned with JNI_ABORT.

Exactly symmetric to the sign path:

Lines 781–790 — Result mapping

OpenSSL returns 1 for valid, 0 for invalid, and a negative value for an error. The code maps these to the public return contract (1/0/-1). An OpenSSL error also triggers setPendingOpenSSLException.

11 · SIGNATURE_reset — re-initialise context (lines 821–868)

JNI JNIEXPORT void JNICALL Java_..._SIGNATURE_1reset(JNIEnv* env, jclass cls, jint fipsFlag, jlong signatureId)

Resets the context to the same state it had immediately after creation, without destroying and re-creating it. This is used by the Java layer when the same key is used for multiple sign/verify operations (e.g. a thread-local context pool).

Lines 839–841 — Clear EdDSA buffer

Only resets dataBufferSize to 0; the allocated capacity of the buffer is kept so the memory doesn't need to be re-allocated next time.

Lines 845 — EVP_MD_CTX_reset

This is a critical OpenSSL 3.x requirement. Before calling EVP_DigestSignInit again on an already-initialised EVP_MD_CTX, the context must be reset first; otherwise OpenSSL 3.x returns an error. The comment explicitly calls this out.

Lines 848–865 — Re-initialise

Calls EVP_DigestSignInit or EVP_DigestVerifyInit with the same md and pkey that were stored at creation time. This re-populates pkeyCtx. If it fails, a Java exception is thrown but the function returns void — the context is now in an indeterminate state and should be deleted by the caller.

12 · SIGNATURE_setPSSParams — RSA-PSS configuration (lines 873–956)

JNI JNIEXPORT jint JNICALL Java_..._SIGNATURE_1setPSSParams(JNIEnv* env, jclass cls, jint fipsFlag, jlong signatureId, jint saltLen, jstring mgf1Digest)

Called by Java after SIGNATURE_create when the algorithm is RSA-PSS. Must be called before any update calls.

Line 886–891 — pkeyCtx guard

pkeyCtx is populated by EVP_DigestSignInit. If it is NULL (e.g. because the context was constructed incorrectly) the call is rejected.

Lines 894–899 — Set PSS padding

EVP_PKEY_CTX_set_rsa_padding(pkeyCtx, RSA_PKCS1_PSS_PADDING) switches the RSA key context from the default PKCS#1 v1.5 padding to PSS. This must come before setting the salt length.

Lines 903–909 — Set salt length

EVP_PKEY_CTX_set_rsa_pss_saltlen(pkeyCtx, saltLen) sets the salt. Java may pass -1 (digest length) or -2 (maximum allowed) as OpenSSL magic values, or any non-negative byte count.

Lines 912–945 — Set MGF1 digest (optional)

If mgf1Digest is not NULL, the digest used inside the PSS mask-generation function is set separately from the outer digest. The function fetches a new EVP_MD*, passes it to EVP_PKEY_CTX_set_rsa_mgf1_md, and then immediately frees it — the pkeyCtx takes its own reference.

Ownership note: The fetched mgf1Md is freed on line 944 regardless of success. OpenSSL takes a reference internally on the set_rsa_mgf1_md call, so this is correct. Failing to free it here would leak one reference.

13 · SIGNATURE_delete — free all resources (lines 961–1006)

JNI cleanup JNIEXPORT void JNICALL Java_..._SIGNATURE_1delete(JNIEnv* env, jclass cls, jint fipsFlag, jlong signatureId)

The destructor. Unconditionally frees everything associated with the context. The FIPS flag is accepted for API consistency but not validated — a delete must always succeed even if the context is half-initialised.

Lines 967–969 — NULL guard

If signatureId is 0 the function returns silently. This lets Java safely call delete on a context that was never successfully created.

Lines 981–985 — Free mdCtx

EVP_MD_CTX_free(mdCtx) also frees the associated EVP_PKEY_CTX that was passed as an out-parameter to EVP_DigestSignInit. The comment on line 984 documents this: pkeyCtx is set to NULL but not freed directly to prevent a double-free.

Lines 988–991 — Free digest

EVP_MD_free decrements the reference count on the digest object. Because fetchDigestSafe acquired a reference at creation time, this is the correct matching release.

Lines 994–997 — Free key

EVP_PKEY_free(pkey) decrements the key's reference count. Since only one reference was taken in loadKeyFromBytes, this frees the key.

Lines 1000 — Free EdDSA buffer

FREE_AND_NULL(signatureCtx->dataBuffer) is a project-defined macro that calls free and sets the pointer to NULL. Safe to call even if dataBuffer is already NULL.

Line 1003 — Free struct

Finally, the OpenSSLSignatureContext struct itself is freed. After this line the signatureId long held by Java is a dangling value; Java is responsible for not using it again.

14 · SIGNATUREEdDSA_signOneShot (lines 1014–1104)

JNI — alternate EdDSA path JNIEXPORT jbyteArray JNICALL Java_..._SIGNATUREEdDSA_1signOneShot(JNIEnv* env, jclass cls, jlong osslContextId, jlong pkeyId, jbyteArray data)

This function provides an alternative EdDSA sign path that accepts an already-loaded EVP_PKEY* handle (pkeyId) rather than raw DER key bytes. It creates and destroys its own EVP_MD_CTX internally; the caller manages the EVP_PKEY lifetime.

When is this used vs. the streaming path? When the Java layer has already loaded the key into a native key object (e.g. via the EC or RSA key factory) and wants to sign with it directly, avoiding a redundant DER serialise/deserialise round-trip.

Lines 1022–1028 — Argument check

Both pkey and data must be non-NULL. The osslContextId parameter is accepted for API symmetry but not used (the EVP_PKEY already carries its context association).

Lines 1030–1035 — Pin data

The data array is pinned and its length queried.

Lines 1037–1055 — Create mdCtx and init

A fresh EVP_MD_CTX is created and initialised with EVP_DigestSignInit(mdCtx, &pkeyCtx, NULL, NULL, pkey). The digest is NULL because EdDSA (RFC 8032) defines its own internal hashing; OpenSSL handles this automatically when the key type is Ed25519/Ed448.

Lines 1057–1068 — Two-call signing

EdDSA has a fixed 64-byte output for Ed25519 and 114 bytes for Ed448, but the code uses the portable two-call pattern:

  1. Size query: EVP_DigestSign(mdCtx, NULL, &sigLen, data, dataLen) — output buffer is NULL; OpenSSL sets sigLen.
  2. Actual sign: EVP_DigestSign(mdCtx, sigBuf, &sigLen, data, dataLen) — output buffer is provided.

Each call cleans up and returns NULL on failure.

Lines 1093–1100 — Copy to Java array

Creates a Java byte[] of exactly sigLen bytes, copies the C buffer into it, then frees the C buffer. Note that if NewByteArray returns NULL (OOM), the result is NULL — the JVM has already thrown OutOfMemoryError, so no additional exception is set.

15 · SIGNATUREEdDSA_verifyOneShot (lines 1114–1187)

JNI — alternate EdDSA path JNIEXPORT jboolean JNICALL Java_..._SIGNATUREEdDSA_1verifyOneShot(JNIEnv* env, jclass cls, jlong osslContextId, jlong pkeyId, jbyteArray sigBytes, jbyteArray data)

Mirror of signOneShot for verification. Returns JNI_TRUE / JNI_FALSE rather than a tri-state integer — the distinction between "invalid" and "error" is collapsed because from the caller's perspective both mean "cannot verify".

Lines 1122–1128 — NULL guards

All three pointer arguments (pkey, sigBytes, data) must be non-NULL.

Lines 1130–1143 — Pin both arrays

Both the signature and the message data are pinned separately. If pinning the data fails after pinning the signature, the signature pin is released before returning.

Lines 1145–1165 — Create mdCtx and init

Same pattern as sign: fresh EVP_MD_CTX, then EVP_DigestVerifyInit(mdCtx, &pkeyCtx, NULL, NULL, pkey).

Lines 1167–1169 — One-shot verify

int rc = EVP_DigestVerify(mdCtx,
    (unsigned char*)sigNat,  (size_t)sigLen,
    (unsigned char*)dataNat, (size_t)dataLen);

All four arguments in one call. OpenSSL verifies the signature over the full message internally.

Lines 1171–1173 — Cleanup

Context and both pinned arrays are released before inspecting rc. This is important: cleanup must happen regardless of the result, and there are no further JNI calls that need the pinned data.

Lines 1175–1186 — Result interpretation

rc == 1 → JNI_TRUE. rc == 0 → JNI_FALSE (clean failure, no exception). rc != 0 && rc != 1 → JNI_FALSE with a pending exception. The comment on line 1179 explicitly marks rc == 0 as a clean verify-failure.

Two EdDSA code paths

PathKey sourceFunctions usedUse case
Streaming + buffered DER bytes passed to create create → update × N → sign/verify Java Signature engine (streaming API compatibility)
One-shot direct Pre-loaded EVP_PKEY* handle SIGNATUREEdDSA_signOneShot / verifyOneShot Direct call from native key objects; avoids DER round-trip

Memory ownership rules

  • EVP_PKEY* — created in loadKeyFromBytes, freed in SIGNATURE_delete. One reference throughout.
  • EVP_MD* — fetched in signature_create_impl, freed in SIGNATURE_delete. Any additional fetch (e.g. in setPSSParams) is freed immediately after use.
  • EVP_MD_CTX* — owns and frees its inner EVP_PKEY_CTX*; do not free pkeyCtx directly.
  • dataBuffer — owned exclusively by the OpenSSLSignatureContext struct; freed in SIGNATURE_delete.
  • JNI arrays pinned with JNI_ABORT — this means "release without copying back", appropriate since the native layer never modifies the Java-side input arrays.
