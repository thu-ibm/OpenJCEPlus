## Summary
Adds an OpenSSL crypto backend to OpenJCEPlus alongside the existing OCK backend.
Implements: MessageDigest (SHA-1/224/256/384/512/SHA3, MD5) via OpenSSL EVP.
Adds: build infrastructure, CI integration, backend selection framework.

## Issues Found

### Critical

1. **`Utils.c` — `int debug = 0; // FIXME`**
   Debug logging is always **off** and always **on** simultaneously: `gslogError` and `gslogMessage`
   always write to stderr regardless of `debug` flag — the flag is never checked. The `// FIXME`
   confirms this is known unfinished work.

2. **`Utils.c` — `vsprintf` buffer overflow risk**
   All three log functions use `static char printBuffer[4096]` with `vsprintf` (no length limit).
   Any format string producing >4095 chars overflows. Should use `vsnprintf`.
   The `static` keyword also makes these functions non-thread-safe.

3. **`Digest.c` — `DIGEST_digest` calls `EVP_DigestFinal_ex` twice on same context**
   ```c
   rc = EVP_DigestFinal_ex(mdCtx, NULL, &digestLen);   // first call — finalizes ctx
   // ...
   rc = EVP_DigestFinal_ex(mdCtx, digestBytesNative, &digestLen);  // second call — UB
   ```
   After `EVP_DigestFinal_ex` the context is finalized. Calling it again with a buffer
   produces undefined behavior. The correct pattern is `EVP_MD_CTX_get_size(mdCtx)` to
   get the digest length, then one `EVP_DigestFinal_ex` with the buffer.

4. **`Utils.c` — `osslCheckStatus` loop condition is wrong**
   ```c
   while ((errCode = ERR_get_error()) == 1) {
   ```
   `ERR_get_error()` returns the error code (never 1 for a real error) or 0 when the queue
   is empty. The loop never executes. Should be `!= 0`.

5. **`NativeOpenSSLAdapter.java` — `osslContextId` hardcoded to 0, native init commented out**
   ```java
   //long osslContextId = NativeOpenSSLImplementation.initializeOSSL(this.useFIPSMode);
   long osslContextId = 0;
   ```
   The OpenSSL library context (OSSL_LIB_CTX) is never created. All JNI calls receive
   `osslContextId=0` and pass `NULL` to `EVP_MD_fetch(NULL, ...)` — which works incidentally
   with the global default context, but FIPS enforcement is impossible without a real context.

### Major

6. **`OpenSSLContext.java` — context is a pure Java wrapper around `osslContextId=0`**
   No native resource, no cleanup. Combined with issue #5, there is no actual OpenSSL library
   context lifecycle management.

7. **`NativeCryptoSelector.java` — non-thread-safe lazy initialization**
   ```java
   if (ockBackend == null) {
       ockBackend = NativeOCKAdapterNonFIPS.getInstance();
   }
   ```
   `ockBackend` is declared `volatile` but the check-then-act is not atomic. Two threads can
   both see `null` and both call `getInstance()`. Should use `synchronized` or
   `java.util.concurrent.atomic` initialization pattern (DCL with volatile is correct only
   with a `synchronized` block, not a bare `if`).

8. **`NativeCryptoSelector.java` — missing `ConfigurationException` import / undefined type**
   `ConfigurationException` is thrown but never imported or defined in the diff. This won't
   compile unless it exists elsewhere.

9. **`NativeOpenSSLImplementation.java` — declares ~1200 lines of native methods for algorithms not yet implemented**
   GCM, CCM, POLY1305, AES, DH, EC, RSA, Signature, HKDF, PBKDF2, KEM — all declared native,
   none implemented in C. The native library only contains `Digest.c` + `Utils.c`. Any call to
   these methods at runtime will throw `UnsatisfiedLinkError`.

10. **`buildNativeWin64.bat` — added `OPENSSL_HOME` check but the mak file uses a different DLL name**
    `openjceplus.win64.cygwin.mak` targets `libopenjceplus_64.dll` but the Windows `pom.xml`
    profile for `ojplib.dir` points to `target\buildwin\ojp-host64\`. The cygwin mak uses
    `cp` — will silently fail under nmake as discussed with OCK. No `mvn` profile was added
    for `win` to use this new library.

### Minor

11. **`Digest.c` — `osslContextId` parameter is accepted but never used**
    Every JNI function receives `jlong osslContextId` but ignores it — all use the global
    default OpenSSL context implicitly. Intentional for now but misleading.

12. **`Utils.c` — `#include <assert.h>` unused**

13. **`Utils.h` — copyright says 2023, 2024 but `Utils.c` says 2026** — inconsistent.

14. **`utils.groovy` — hardcoded MSVC path version `14.44.35207`**
    ```groovy
    c:\\Program Files\\Microsoft Visual Studio\\2022\\Professional\\VC\\Tools\\MSVC\\14.44.35207\\bin\\...
    ```
    Will break on any CI agent with a different VS patch version.

15. **`.github/workflows` — OpenSSL headers installed via `apt` then manually `cp`'d**
    Over-engineered and fragile. Should just set `OPENSSL_HOME=/usr` or use the installed
    pkg-config paths directly.

16. **`pom.xml` — `consoleOutputReporter.disable` changed from `true` to `false`**
    Enables verbose test console output for all builds — likely unintentional, should be reverted.
